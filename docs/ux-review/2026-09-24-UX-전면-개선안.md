## 0. 총평

**한 줄 진단: 기능은 많이 쌓였는데, "오늘 할 일을 적고 하나씩 지운다"는 핵심 루프가 그 기능들에 묻혀 있다.**

직접 보고 느낀 가장 큰 불편 5가지:

1. **할 일 하나 추가하는 데 화면이 너무 무겁다.** Cmd+N → "무엇을 추가할까요?" 시트 → 20개 컨트롤이 펼쳐진 시트. 모바일에서는 시트가 화면 전체를 덮고 저장 버튼이 키보드 밖으로 밀린다. (`v_mobile_05_add_sheet.png`, `v_mobile_06_edit_sheet.png`)
2. **할 일 한 줄이 너무 시끄럽다.** 컬러바 + 제목 + 메모 아이콘 + 진행중 pill + 날짜 + 하위 pill + ↳ + △ + ○ + ⋮ 가 모든 행에 상시 노출. 모바일에서는 버튼 4개가 144dp 를 먹어 제목이 항상 2줄로 잘린다. (`v_mobile_01_today.png`)
3. **같은 데이터를 보여주는 화면이 4~5개인데 모양·조작이 전부 다르다.** 오늘 / 카테고리 / 전체보기 / 그룹 화면 / 타임라인 / 검색. 체크 위치(좌·우), 삭제 가능 여부, breadcrumb 유무가 화면마다 다르다.
4. **macOS 가 메인인데 모바일 패턴이 그대로다.** 하단 시트, FAB, 바텀시트 컨텍스트 메뉴, 전체 화면 push(사이드바를 덮음), 다이얼 시간 선택기. Cmd+, / 메뉴바 / 우클릭 / Cmd+Enter 없음.
5. **데이터를 잃거나 의도와 반대로 동작하는 지점이 있다.** 편집 시트 "취소"가 실제로는 저장, "이동" 누르면 편집 중이던 내용 폐기, 섹션 간 드래그로 카테고리가 확인 없이 바뀜, Cmd+N 을 OS 전역으로 잡아 다른 앱의 Cmd+N 을 가로챔.

자가 점수(솔직하게): **디자인 6.5 / 편의성 6.0**. 토큰·간격·색은 잘 잡혀 있어(theme.dart) 기초 체력은 좋다. 문제는 **정보 밀도 배분과 동선 설계**라서, 코드 리팩토링보다 "무엇을 빼고 어디로 옮길지" 결정이 핵심이다.

## 1. 개선 방향 (원칙)

| # | 원칙 | 적용 |
|---|------|------|
| P1 | **오늘 화면 = 종이 체크리스트** | 오늘 화면에서는 카테고리 색·pill·보조 버튼을 최소화. 제목 + 체크 + (있으면) 시간만. 나머지는 hover / 스와이프 / 메뉴로. |
| P2 | **빠른 추가는 1줄, 상세는 펼쳐서** | 제목 한 줄 + 인라인 칩(오늘·내일·시간·카테고리)만 기본. 메모/반복/기간/캘린더는 "더보기"로 점진 노출. |
| P3 | **행 컴포넌트 하나(TodoTile)를 전 화면이 공유** | 전체보기 `_OutlineNode`, 타임라인 `_TimelineTile`, 캘린더 패널 타일을 TodoTile 변형(density: compact/regular)으로 통일. 체크 위치·색·메뉴·스와이프 규칙 동일. |
| P4 | **데스크탑은 데스크탑답게** | 우측 인스펙터(편집 패널), 우클릭 컨텍스트 메뉴, Cmd+1~9 / Cmd+Enter / Cmd+, / Cmd+Z, hover 시에만 보조 버튼, 메인 영역 내부 Navigator(사이드바 유지). |
| P5 | **파괴적·비가역 동작에는 항상 되돌리기** | 완료 체크, 카테고리 이동(드래그), 그룹/카테고리 삭제, 연결 해제, 반복 중지 전부 Undo 스낵바 또는 확인. |
| P6 | **상태 기호는 한 벌만** | □ 미완료 / △ 진행중 / ● 완료 를 전 화면에서 같은 위치·같은 컴포넌트로. 타일에서는 **체크 하나**로 두고 진행중은 우클릭·롱프레스·메뉴로. |
| P7 | **화면 수를 줄인다** | 그룹 화면(=전체보기 필터)·타임라인(=캘린더 목록)은 독립 화면 대신 기존 화면의 필터/세그먼트로 흡수. |

## 3. 공통 디자인 시스템 개선

### 3-1. 타이포
- `labelSmall` 이 theme 에 없어 M3 기본 **11sp** 가 pill·breadcrumb·그룹 라벨·힌트에 쓰인다 (`theme.dart:255-281`). → `labelSmall: 12 w500 muted` 정의, 모바일 최소 12, 데스크탑 pill 은 12~13.

## 4. 화면별 개선안

### 4-1. 앱 셸 (사이드바 · 네비 · 단축키 · 추가 진입)

**현재** (`v_desktop_01_today.png`, `v_mobile_10_drawer.png`)
- FAB "+ 추가" / Cmd+N → "무엇을 추가할까요?"(할 일 / 카테고리 / 그룹) → 추가 시트. 트레이는 바로 시트. (`app_shell.dart:454-477, 90-92`)
- 사이드바 220px 고정, 그룹 아코디언(하나만 펼침), 카테고리 행마다 ⠿ 상시 노출, 그룹 소속 카테고리 들여쓰기 없음.
- 숫자키 0~9 (modifier 없음). 주석과 실제 매핑 불일치(`app_shell.dart:36` vs `destination.dart:61-92`).
- 모바일 하단 네비 4번째 슬롯은 이동이 아니라 Drawer 열기. AppBar 제목 + 화면 헤더 제목 이중.

**개선**
1. **Cmd+N / FAB / 트레이 = 즉시 "새 할 일"**. 카테고리·그룹 추가는 사이드바 하단 "+ 카테고리" / 그룹 헤더 ⋮ / Drawer 하단 버튼으로 이동. (`_AddActionSheet` 제거)
2. **단축키를 macOS 관례로**: Cmd+1~9 destination, Cmd+N 새 할 일, Cmd+F 검색(오버레이), Cmd+, 설정, Cmd+Z 되돌리기, Cmd+Enter 저장, Esc 닫기. `PlatformMenuBar` 로 메뉴바에 노출(단축키 발견성 해결).
3. **사이드바**: 그룹 소속 카테고리 들여쓰기(12px) + 여러 그룹 동시 펼침 + 펼침 상태 저장(shared_preferences 패턴 `[[no-settings-persistence-infra]]`). ⠿ 는 hover 시에만. "오늘" 옆 미완료 배지. 하단에 "보관함 (N)" 진입점. 그룹 헤더 탭 = 펼침만, 그룹 화면 이동은 별도(§4-6).
4. **모바일**: AppBar 제목만 남기고 본문 큰 헤더 제거(오늘·전체보기·카테고리·그룹 공통, 약 100dp 절약). 4번째 슬롯은 "카테고리" 고정 라벨 + 탭하면 카테고리 **목록 화면**(Drawer 아님). Drawer 는 ☰ 로만.
5. FAB: 데스크탑에서는 제거(Cmd+N + 사이드바 하단 "새 할 일" 버튼). 모바일은 유지하되 마지막 타일이 가리지 않도록 하단 여백 88.
6. 카테고리 삭제 차단 문구 "todos 부터 삭제" → "할 일 N개를 '일상'으로 옮기고 삭제 / 대신 보관" 선택지 제공.

### 4-2. 오늘 화면

**현재** (`v_desktop_01_today.png`, `v_mobile_01_today.png`)
- 헤더 "오늘"(28 w800) + 날짜 + 🔁 → 진척 카드(링 2/8 + "오늘 2 / 8 완료" + "25%" 세 번 반복) → 이월 배너(행동 없음) → 카테고리 섹션(헤더마다 미니바+분수) → 타일.
- 완료 항목이 미완료 사이에 섞여 남음. 정렬·필터·완료접기 없음(카테고리 화면에는 있음).
- 모바일: 첫 화면에서 실제 할 일이 보이기까지 약 380dp 소모.

**개선**
```
┌ 오늘  9월 24일 (목)                        ○ 6 남음 · 2 완료   [일정순▾] ┐
│ ⟳ 어제 1건 이월됨   [보기] [모두 내일로]                                    │
│                                                                           │
│ 회사 할일 ─────────────────────────────────────────────────── 1/4          │
│  ○ 결제 API 리팩토링 PR 리뷰            14:00   ▸ 하위 2                   │
│  ○ 주간 스프린트 회의                   15:00–16:00                        │
│  ○ 어제 못 끝낸 QA 이슈 정리            ⟳ 이월                              │
│ 개인개발 ──────────────────────────────────────────────────── 0/2          │
│  ○ 하루 앱 캘린더 드래그 버그 수정       진행중                              │
│  …                                                                        │
│ ▸ 완료 2개                                                                 │
└───────────────────────────────────────────────────────────────────────────┘
```
1. 진척 표시는 **한 줄 텍스트 + 얇은 바**로 축소 (카드 제거). 링·퍼센트·분수 중 하나만. 탭하면 "남은 것만 보기" 필터.
2. 섹션 헤더: 아이콘 배지 제거, 이름 + 얇은 진척 텍스트만. 헤더 탭 → 카테고리 화면. 접기 가능.
3. **완료 항목은 하단 "완료 N개" 접기 행으로** (카테고리 화면과 동일 규칙, 당일 완료 유지 `[[done-collapse-browsing-views]]`).

**개선**

### 4-4. 추가 / 편집 시트 — 가장 큰 개편

**현재** (`v_desktop_05/06`, `v_mobile_05/06`): 20~38개 컨트롤 상시 노출. 날짜 UI 3겹(모드 칩 4 + 빠른 칩 4 + 날짜 행/시간 버튼). 시간 넣는 길 3개, 하루종일로 돌아가는 길 2개. 모드 칩만 눌러도 날짜가 생김. 반복은 추가 모드+날짜 있을 때만, 편집 시 수정 불가. 캘린더 토글 라벨 "Google Calendar" 고정. 모바일 편집 시트가 화면을 넘침.

**개선 — 2단 구조**
```
┌ 새 할 일 ──────────────────────────────────────────── (회사 할일 ▾) ┐
│ ┌──────────────────────────────────────────────────────────────┐   │
│ │ 무엇을 할까요?                                                 │   │
│ └──────────────────────────────────────────────────────────────┘   │
│  [오늘] [내일 (금)] [다음주 월] [📅 날짜…]  [⏰ 시간]   [메모로 ⇄]     │
│                                                                    │
│  ▸ 더보기 (설명 · 기간 · 반복 · 캘린더 등록)                          │
│                                                     [닫기] [추가 ⌘↩] │
└────────────────────────────────────────────────────────────────────┘
```
1. **1단(항상)**: 제목 + 카테고리 드롭다운(헤더 우측, 현재 화면 기준 기본값) + 날짜 빠른 칩(실제 요일 병기) + 시간 칩 + 종류 토글. 컨트롤 8개.
2. **2단(더보기, 상태 기억)**: 설명, 기간(시작~종료), 반복(요약 한 줄 + 편집), 캘린더 등록(연결된 서비스명 동적 표시, 미연결이면 "연결하기" 링크), 상태(편집 모드).
3. **날짜 모델 단순화**: "날짜 → (선택) 시간 → (선택) 종료" 순서. 모드 칩(하루종일/시작/마감/기간) 제거. 시작·마감 구분은 시간 칩 안의 작은 토글("시작 14:00" / "마감 14:00"). 날짜 행에 시작·마감 라벨 명시.
4. **시간 입력**: 데스크탑은 텍스트 입력(`TimePickerEntryMode.input`) + "14", "2pm", "오후 2시" 파싱. 모바일은 다이얼 유지.
5. **키보드**: Enter = 저장(제목), Cmd+Enter = 저장(어디서든), Esc = 닫기, Tab 순서는 제목 → 날짜 → 시간 → 저장(칩 20개 순회 제거).
6. **저장 모델 한 벌**: 편집 = 닫힘 저장(기존 정책 유지) + 버튼 라벨 "닫기". 추가 = 제목이 비어있지 않은데 닫으면 "입력을 버릴까요?" 확인(또는 초안 보존). 상태 칩 즉시 저장은 유지하되 "저장됨" 마이크로 피드백.
7. **편집 모드에서 반복 추가·수정 가능**. 요약("2주마다 월·수, 12/31까지") + 편집 버튼. `rule.describe` 재사용.
8. 카테고리 변경 시 부수효과(하위 항목 분리, 자손 카테고리 동기화)를 인라인 안내. 위치 이동은 "이동" 하나로 통합(카테고리 칩과 중복 제거).
9. 헤더 제목: "새 할 일 / 새 메모 / '결제 API…' 의 하위 추가 / 할 일 편집 / 복사".
10. 용어 분리: 종류 "메모" ↔ 필드 "상세 메모" → 필드는 **"설명"** 으로.
11. 편집 시트에 ⋮(삭제 · 복사 · 이동). 삭제는 Undo.
12. 편집 진입 시 `autofocus` 끄기(모바일 키보드가 시트 절반을 가림). 제목 maxLength 도달 시 카운터 노출.
13. 데스크탑: 하단 시트 대신 **우측 인스펙터**(사이드바 유지, 목록 보며 편집) 또는 중앙 다이얼로그.

3. 캘린더 연동: 공용 옵션(초대 가져오기 · 자동 동기화)을 "공통" 섹션으로 분리. 서비스 카드에 계정 이메일 · 마지막 동기화(날짜+시각) · 상태(정상/재인증 필요/오류) · "지금 동기화" 결과 스낵바. 연결 해제는 확인 창 + 대기 큐 경고. 데스크탑 연결 중 "브라우저에서 계속하세요 · 취소".
4. 보관함: 사이드바/Drawer 하단 진입, 로딩 skeleton, 보관 그룹 펼쳐서 카테고리 개별 복원, 항목 수 표시, 영구 삭제. 빈 상태 문구 "길게 눌러" → 실제 경로(⋮ 메뉴)로 정정.
5. 로그인: 브랜드 아이콘(`assets/branding`), 해요체 통일, 자릿수 문구 정정, 코드 재전송(60초 카운트다운), 오류는 필드 errorText + 한국어 매핑, 세션 복원 중 스플래시(로그인 화면 깜빡임 방지).
6. 트레이: "하루 열기", 오늘 남은 할 일 상위 5개(체크 가능), 동기화 상태, 설정, 라벨 "새 할 일 ⌘N" 과 실제 동작 일치. `window_manager` 로 창 표시.
