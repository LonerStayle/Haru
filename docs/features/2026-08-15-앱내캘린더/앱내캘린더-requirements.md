## 1. 배경 / 문제

이 앱에는 **날짜를 달력 격자로 보는 화면이 없다.** 현재 날짜 관련 화면은 `타임라인` 하나뿐이고, 그것은 "날짜가 지정된 미완료 할 일"을 `지남 / 오늘 / 내일 / 이번주 / 이후` 버킷으로 **나열**하는 리스트다.

리스트 뷰만으로는 다음이 안 된다.

| 못 하는 것 | 왜 문제인가 |
|---|---|
| "이번 달 어느 날이 비어 있는가" 파악 | 새 일정을 넣을 날을 고를 때 매번 추측해야 함 |
| 특정 날짜를 직접 지목해서 할 일 추가 | 추가 시트를 열고 날짜 피커를 따로 조작해야 함 |
| 날짜를 옮기는 동작 | 편집 시트 → 날짜 피커 → 저장, 3단계 |
| 과거 달의 성취 조망 | 타임라인은 미완료만 보여줌 |
| 구글 캘린더 일정과 내 할 일의 충돌 확인 | 두 앱을 번갈아 봐야 함 |

## 2. 목표 (Goal)

**월 달력 격자를 중심으로, 날짜를 "보고 · 고르고 · 옮기는" 것이 한 화면에서 끝나는 캘린더 화면을 만든다.**

성공 판정 (대표님 자가 평가, `CLAUDE.md` §4 기준):
- 디자인 점수 ≥ 9 / 10 (가독성·가시성)
- 편의성 점수 ≥ 9 / 10 (단축 동작·반응성)

## 3. 비목표 (Non-goal)

- 구글 캘린더 **양방향 동기화** — 별도 워크트리 `구글캘린더동기화`의 영역. 이 화면은 **읽기 전용 표시**까지만.
- 주 뷰 / 일 뷰 — 이번 범위 밖 (§5 R-2 참조). 나중에 확장 가능하도록 구조만 열어둔다.
- 시간축(타임라인 그리드) 렌더링 — 시각 겹침 배치 로직 없음.
- 새 Drift 스키마 컬럼 추가 — 필요하다고 판단되면 **구현 전에 대표님께 보고**하고 승인받는다.

## 5. 확정된 요구사항

### R-1. 타임라인 흡수 — 캘린더가 `타임라인` destination 을 대체한다

- `DestinationKind.timeline` → `DestinationKind.calendar` 로 **교체**한다. destination 개수는 그대로 (데스크탑 사이드바 / 모바일 nav 4칸 유지, 단축키 `2` 유지).
- 기존 타임라인 버킷 뷰는 **삭제하지 않는다.** 캘린더 화면 상단의 **세그먼트 토글 `[달력] [목록]`** 중 `목록` 쪽에 그대로 살려둔다.
- 세그먼트 선택 상태는 **세션 내에서만** 유지한다 (앱 재시작 시 `달력`으로 복귀). 영속 저장 안 함.

```
nav: 오늘 · 전체보기 · 캘린더 · 카테고리
                       └ [달력] / [목록] 세그먼트
```

**근거**: 모바일 `NavigationBar` 가 이미 4칸 고정이라 destination 을 늘리면 라벨이 압축된다. 흡수 방식은 자리 문제도, 기능 손실도 없다.

### R-2. 뷰 범위 — 월 그리드 + 선택일 목록

- **월 그리드** (7열 × 5~6행) + **선택된 날짜의 할 일 목록**, 두 영역으로 구성.
- 레이아웃 분기 (`AppPlatform`):
  - **데스크탑**: 좌우 분할 (좌 = 달력, 우 = 선택일 목록)
  - **모바일**: 상하 분할 (상 = 달력, 하 = 선택일 목록). 달력 영역은 **접기 가능**하여 목록을 넓게 볼 수 있어야 한다.
- 주 뷰 / 일 뷰는 만들지 않는다.

### R-3. 인터랙션 — 4종 전부 필수

| # | 동작 | 상세 |
|---|---|---|
| R-3-a | **날짜 탭 → 그날 목록** | 셀 탭 시 선택일이 바뀌고 목록 영역이 그 날짜로 갱신. 목록의 항목 탭 → **기존 편집 시트** 재사용 (닫으면 저장 규칙 유지) |
| R-3-b | **빈 날짜 탭/길게 → 그 날짜로 추가** | 날짜를 길게 누르면(데스크탑은 목록 영역의 `＋ 이 날짜로 추가` 버튼도 제공) `dueAt` 이 그 날짜로 **미리 채워진** 추가 시트가 열린다. 날짜 입력 단계를 통째로 생략하는 것이 핵심 가치 |
| R-3-c | **드래그로 날짜 변경** | 목록 / 날짜없음 서랍의 항목을 달력 셀에 드롭하면 `dueAt` 이 그 날짜로 바뀐다. 시각(hh:mm)과 `isAllDay` 는 **보존**한다 (날짜 부분만 교체) |
| R-3-d | **월 이동** | 모바일 = 좌우 스와이프, 데스크탑 = `←` / `→` 키. 양 플랫폼 공통으로 헤더의 `‹ ›` 버튼 + `오늘` 버튼(단축키 `T`) 제공 |

### R-4. 표시 대상 — 4종 전부 표시

| # | 대상 | 표시 규칙 |
|---|---|---|
| R-4-a | **완료 항목** | 달력·목록 양쪽에 표시하되 **취소선 + 흐린 색**으로 구분. (미완료와 시각적으로 명확히 구분되어야 함) |
| R-4-b | **메모(note) 타입** | `dueAt` 이 있으면 표시. 체크박스 대신 **메모 아이콘**으로 task 와 구분. `isDone` 개념 없음 |
| R-4-c | **반복 인스턴스** | 반복 일정은 해당 날짜마다 전부 표시. **`isSeriesMaster == true` 는 언제나 제외** (전 앱 불변 규칙) |
| R-4-d | **기간 항목** | `dueAt` ~ `endAt` 이 여러 날에 걸치면 **가로 막대**로 연결해 그린다. 주 경계에서 끊기고 다음 주 첫 칸에서 이어진다 |

공통 제외 규칙 (기존 화면들과 동일):
- 보관(archived) 카테고리에 속한 항목 제외 (`archivedCategoryIdsProvider`)
- `isSeriesMaster == true` 제외

### R-5. 구글 캘린더 이벤트 — 읽기 전용으로 함께 표시

- 구글 캘린더 이벤트를 조회해 달력·선택일 목록에 **다른 색 계열**로 함께 표시한다. **편집·삭제·이동 불가** (탭하면 상세만, 또는 무반응).
- 로컬 Todo 와 시각적으로 명확히 구분되어야 한다 (예: 좌측 색 바 대신 아웃라인 스타일 + 구글 아이콘).
- **머지 충돌 회피 제약 (중요)**: 별도 워크트리 `구글캘린더동기화`가 `lib/src/features/calendar/calendar_service.dart` · `google_auth_service.dart` 를 담당한다.
  - 이 워크트리는 위 두 파일을 **수정하지 않는다.**
  - 이벤트 조회 레이어는 **신규 파일**로만 추가한다 (인증 클라이언트만 기존 것을 재사용).
  - 기존 파일 수정이 불가피해지면 **구현 전에 대표님께 보고**한다.
- **실패는 조용히**: 미로그인 / 네트워크 실패 / 토큰 만료 시 캘린더 화면은 **로컬 Todo 만으로 정상 동작**해야 한다. 에러 배너로 화면을 막지 않는다.
- 이벤트 표시 on/off 토글을 화면 내에 둔다 (기본값: 구글 연동이 이미 켜져 있으면 on).

### R-6. 날짜 없는 할 일 — 하단 "날짜 없음" 서랍

- `dueAt == null` 인 항목을 화면 하단의 **접을 수 있는 서랍**에 모은다. 헤더는 `▾ 날짜 없음 (N)`.
- 기본 상태는 **접힘**. 펼침 상태는 세션 내에서만 유지.
- 서랍의 항목을 달력 셀로 **드래그 드롭하면 그 날짜가 부여**된다 (R-3-c 와 같은 경로).
- 서랍에도 R-4 의 제외 규칙(보관 / seriesMaster)이 동일 적용된다.

### R-7. 칸 밀도 — 데스크탑은 제목 칩, 모바일은 점

| 플랫폼 | 표현 | 상한 |
|---|---|---|
| **데스크탑** | 카테고리 색 좌측 바 + 제목 칩 | 최대 3개 + `외 N건` |
| **모바일** | 카테고리 색 **점** | 최대 4개, 초과 시 4번째를 `+` 형태나 크기로 암시 |

- 기존 "기능은 양쪽 parity, 폭·줄 수·터치 타겟만 모바일 압축" 규칙과 일치.
- 셀 높이는 **모든 주 행이 균일**해야 한다 (내용에 따라 들쭉날쭉하면 안 됨).

### R-8. 시각적 규칙

- **오늘 날짜**는 항상 눈에 띄게 강조 (선택일과 다른 표현). 선택일 강조와 오늘 강조가 동시에 보여야 한다.
- 이전 달 / 다음 달의 넘침 날짜는 흐리게 표시하되 탭하면 그 달로 이동한다.
- **`00:00` 을 화면 어디에도 찍지 않는다** (`isAllDay == true` 인 항목의 시간 미표시 규칙 — 전 앱 불변).
- 날짜 라벨 포맷은 `lib/src/core/date_format.dart` 를 **단일 출처**로 쓴다. 새 포맷이 필요하면 그 파일에 추가한다.
- 주 시작 요일은 **일요일**로 고정한다 (별도 설정 없음).

### R-9. 미래 반복 회차 — 건드는 순간 실체화

이 앱의 반복은 **하이브리드**다. 과거~오늘 회차만 실제 `todos` row 로 만들어지고, **미래 회차는 DB 에 존재하지 않는다** (런타임 계산). 따라서 캘린더의 미래 반복은 "실체 없는 예정 표시(고스트)"다.

- 미래 반복 고스트는 **점선 / 흐린 테두리**로 실체 항목과 구분해 표시한다.
- 고스트를 **탭 · 체크 · 드래그하는 순간 그 회차만 실제 항목으로 생성**되고, 그 다음 원래 동작이 적용된다.
- 다른 회차는 그대로 예정 상태로 남는다.
- **알려진 한계 (대표님 승인함)**: 이미 손댄 미래 회차는 실체 row 가 되므로, 이후 반복 규칙을 바꿔도 그 자리에 **예외로 잔존**한다.
