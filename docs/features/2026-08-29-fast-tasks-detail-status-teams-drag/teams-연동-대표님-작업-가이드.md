# Teams(Microsoft 365) 캘린더 연동 — 대표님 작업 가이드

**소요 시간** 약 15분 (Azure 등록 10분 + 앱 설정 5분)
**준비물** 회사 Microsoft 365 계정, 웹 브라우저, `haru` 저장소의 `.env.local` 파일
**끝나면** 하루 앱의 할 일이 Outlook/Teams 캘린더에 자동으로 등록되고, 캘린더에서 고치거나 지운 것도 앱으로 되돌아옵니다. 구글 캘린더 연동은 그대로 함께 동작합니다.
**비용** 없습니다. Azure 앱 등록(Microsoft Entra ID)도, Graph API 캘린더 호출도 무료이며 Azure 유료 구독이 필요 없습니다. 포털에서 "구독을 만드세요" 안내가 보여도 무시하십시오 — 돈이 드는 것은 가상머신 같은 리소스를 만들 때뿐이고, 이 연동은 그런 것을 만들지 않습니다.
**막히면** 맨 아래 "자주 나는 실패 → 대처" 표를 먼저 보십시오.

---

## STEP 1. Azure 앱 등록 만들기

1. 브라우저에서 **https://portal.azure.com** 에 회사 계정으로 로그인합니다.
2. 상단 검색창에 **`앱 등록`** 을 입력하고 나오는 **앱 등록(App registrations)** 을 클릭합니다.
3. 위쪽 **`+ 새 등록`** 을 클릭합니다.
4. 아래대로 입력합니다.
   - **이름**: `하루 (Haru)`
   - **지원되는 계정 유형**: **`이 조직 디렉터리의 계정만`** 을 선택합니다.
     ⚠️ **여기서 `개인 Microsoft 계정만` 을 고르면 회사 계정으로 로그인할 수 없습니다** (연결 시 `AADSTS9002346` 으로 튕깁니다). 잘못 골랐어도 나중에 매니페스트의 `signInAudience` 를 `AzureADMyOrg` 로 고치면 됩니다.
   - **리디렉션 URI**: **비워 둡니다** (STEP 3 에서 넣습니다).
5. 맨 아래 **`등록`** 을 클릭합니다.

---

## STEP 2. 클라이언트 ID / 테넌트 ID 복사하기

1. 등록이 끝나면 바로 **개요(Overview)** 화면이 열립니다.
2. 아래 두 값을 각각 복사해 메모장에 붙여 둡니다.
   - **애플리케이션(클라이언트) ID** — 예: `11111111-2222-3333-4444-555555555555`
   - **디렉터리(테넌트) ID** — 예: `aaaaaaaa-bbbb-cccc-dddd-eeeeeeeeeeee`
3. 두 값 모두 GUID 형태입니다. STEP 5 에서 씁니다.

---

## STEP 3. 리디렉션 URI 등록하기 (macOS · Android 공통)

앱은 `http://localhost:<그때그때 비는 포트>` 로 인증 결과를 돌려받습니다. Azure 에는 **포트 없이** `http://localhost` 하나만 등록하면 됩니다 — Azure 는 loopback 주소를 포트와 무관하게 매칭합니다. `http://localhost:8080` 처럼 포트를 박으면 오히려 실패합니다. macOS 와 Android 가 같은 값을 쓰므로 플랫폼별로 따로 등록할 것이 없습니다.

### 방법 A — 인증 화면에서 (기본)

1. 왼쪽 **`관리(Manage)`** 섹션의 **`인증(Authentication)`** 을 클릭합니다.
   (왼쪽 메뉴가 안 보이면 창을 최대화하거나 좌측 상단 `≡` 로 펼치십시오. 메뉴에 `사용자 및 그룹` · `Single sign-on` 이 보이면 **엔터프라이즈 애플리케이션** 화면이니 `앱 등록` 으로 다시 들어가야 합니다.)
2. **`플랫폼 구성`** 아래 **`+ 플랫폼 추가`** → **`모바일 및 데스크톱 애플리케이션`** 을 클릭합니다.
3. 리디렉션 URI 체크박스 목록에서 **`http://localhost`** 를 **체크**합니다.
   (이 값이 목록에 이미 있습니다. 없다면 아래 `사용자 지정 리디렉션 URI` 칸에 `http://localhost` 를 직접 넣으셔도 결과는 같습니다. `nativeclient` 나 `msal...://auth` 항목은 체크하지 않습니다.)
4. **`구성`** 을 클릭합니다.
5. 같은 화면 아래쪽 **`고급 설정`** 의 **`공개 클라이언트 흐름 허용`** 을 **`예`** 로 바꾸고 위쪽 **`저장`** 을 클릭합니다.

### 방법 B — 매니페스트로 직접 (플랫폼 추가 버튼이 안 보일 때)

1. 왼쪽 **`관리 → 매니페스트(Manifest)`** 를 엽니다.
2. 화면 상단이 **`Microsoft Graph 앱 매니페스트`** 형식이면 아래 두 곳을 찾아 그대로 맞춥니다.

```json
"publicClient": {
    "redirectUris": [
        "http://localhost"
    ]
},
"isFallbackPublicClient": true,
```

3. 상단이 **`AAD 그래프 앱 매니페스트(사용 중단)`** 형식이면 이렇게 합니다.

```json
"replyUrlsWithType": [
    {
        "url": "http://localhost",
        "type": "InstalledClient"
    }
],
"isFallbackPublicClient": true,
```

4. **`저장`** 을 클릭합니다. 두 방식의 결과는 같으며, `isFallbackPublicClient: true` 가 방법 A 의 **공개 클라이언트 흐름 허용 = 예** 와 같은 설정입니다.
5. 이미 그 키가 있으면 값만 고치고, 배열이 비어 있으면 위 항목을 넣습니다. **쉼표 위치**만 주의하십시오 — JSON 문법이 깨지면 저장이 거부됩니다.

> **어느 방법이든 확인법은 같습니다.** `인증` 화면에 **모바일 및 데스크톱 애플리케이션** 항목과 그 아래 `http://localhost` 가 보이면 성공입니다.

## STEP 4. API 권한 주기

1. 왼쪽 메뉴에서 **`API 권한(API permissions)`** 을 클릭합니다.
2. **`+ 권한 추가`** → **`Microsoft Graph`** → **`위임된 권한`** 을 클릭합니다.
3. 검색창에 하나씩 입력해 아래 **3개**를 체크합니다.

```
Calendars.ReadWrite
offline_access
User.Read
```

4. 아래 **`권한 추가`** 를 클릭합니다.
5. 목록의 **상태** 열을 확인합니다.
   - 초록 체크(`<조직명>에 부여됨`)면 이대로 끝입니다.
   - **`관리자 동의 필요`** 라고 뜨면 위쪽 **`<조직명>에 대한 관리자 동의 허용`** 버튼을 클릭합니다.
   - 그 버튼이 비활성이면 대표님 계정에 관리자 권한이 없다는 뜻입니다 — 회사 IT 담당자에게 **"Microsoft Graph 위임 권한 Calendars.ReadWrite / offline_access / User.Read 에 관리자 동의를 부탁드립니다"** 라고 요청하십시오.

---

## STEP 5. `.env.local` 에 값 넣기

1. `haru` 저장소 루트의 **`.env.local`** 파일을 엽니다. (없으면 `.env.example` 을 복사해 만듭니다.)
2. 파일 끝에 아래 두 줄을 추가하고, `=` 뒤에 STEP 2 에서 복사한 값을 붙여 넣습니다.

```
MS_OAUTH_CLIENT_ID=여기에_애플리케이션_클라이언트_ID
MS_OAUTH_TENANT=여기에_디렉터리_테넌트_ID
```

3. 저장합니다. 키 이름은 **정확히 위 두 개**입니다 (대소문자 포함).

> `MS_OAUTH_TENANT` 는 비워 두거나 `organizations` 로 두어도 동작합니다. 다만 회사 테넌트 ID 를 넣으면 다른 계정으로 잘못 로그인하는 일을 막아 줍니다.

---

## STEP 6. Supabase 스키마 갱신하기 (건너뛰면 동기화가 멈춥니다)

1. 터미널에서 저장소 루트로 이동해 다음을 실행합니다 — `supabase/schema.sql` 이 클립보드에 복사됩니다.

```
make sql
```

2. **https://supabase.com/dashboard** → 해당 프로젝트 → 왼쪽 **`SQL Editor`** 를 엽니다.
3. 붙여 넣고 **`Run`** 을 클릭합니다. (전체가 여러 번 실행해도 안전한 스크립트입니다.)
4. 마지막 줄에 오류가 없으면 완료입니다.

> 이 단계를 건너뛰면 **할 일 동기화 전체가 멈춥니다** (`PGRST204` 오류). 과거에 같은 원인으로 동기화가 며칠간 죽은 적이 있습니다.

---

## STEP 7. 앱 다시 빌드하고 연결하기

1. 터미널에서 아래를 실행합니다.

```
flutter clean && flutter pub get
```

2. macOS 에서 실행합니다.

```
make run
```

3. 앱에서 **톱니(설정) → `Microsoft 365`** 를 누릅니다.
4. **`Microsoft 회사 계정 연결`** 을 누르면 브라우저가 열립니다.
5. 회사 계정으로 로그인하고 **`수락`** 을 누릅니다.
6. 브라우저에 **"연결되었습니다"** 가 뜨면 창을 닫고 앱으로 돌아옵니다.
7. Android 도 쓰시려면 아래를 실행해 폰에 다시 설치한 뒤 같은 순서로 연결하십시오.

```
make build-apk
flutter install
```

## 확인 체크리스트

아래가 모두 보이면 정상입니다.

- [ ] 설정 화면에 **`Microsoft 365`** 항목이 보인다 (안 보이면 `MS_OAUTH_CLIENT_ID` 가 빌드에 안 들어간 것입니다 — STEP 5 + STEP 7 재확인).
- [ ] 항목을 눌렀을 때 초록 점과 **`연결됨`** 이 보인다.
- [ ] **`할 일을 등록할 캘린더`** 드롭다운에 Outlook 캘린더 이름이 나온다.
- [ ] **`가져올 캘린더`** 목록에 캘린더가 뜨고, 원하는 것에 체크가 되어 있다.
- [ ] 앱에서 **날짜가 있는 할 일**을 하나 만들고 **`지금 동기화`** 를 누르면, 1분 안에 Outlook 캘린더에 같은 제목의 일정이 생긴다.
- [ ] Outlook 에서 그 일정의 제목을 바꾸고 **`지금 동기화`** 를 다시 누르면, 앱의 할 일 제목도 바뀐다.
- [ ] 구글 캘린더 연동도 그대로 동작한다 (설정에 **`Google Calendar`** 항목이 따로 남아 있습니다).

두 서비스를 모두 연결하면 설정 화면에 **`새 할 일을 올릴 캘린더`** 드롭다운이 생깁니다. 새로 만드는 할 일이 어느 쪽으로 갈지 여기서 고르시면 됩니다. 이미 한쪽에 등록된 할 일은 계속 그쪽으로만 동기화됩니다.

## 자주 나는 실패 → 대처

| 증상 | 원인 | 대처 |
|---|---|---|
| 설정에 **Microsoft 365 항목이 아예 없음** | `MS_OAUTH_CLIENT_ID` 가 빌드에 안 들어감 | `.env.local` 에 키가 있는지 확인 → `flutter clean` 후 다시 빌드 (증분 빌드는 옛 값을 씁니다) |
| 브라우저에 **`AADSTS50011: redirect URI 가 일치하지 않습니다`** | 리디렉션 URI 미등록 또는 포트를 박음 | STEP 3 을 다시 확인. 플랫폼은 **모바일 및 데스크톱 애플리케이션**, 값은 포트 없는 **`http://localhost`** |
| **`AADSTS65001: 사용자 또는 관리자가 동의하지 않았습니다`** | 조직이 관리자 동의를 요구 | STEP 4 의 **관리자 동의 허용** 클릭. 권한이 없으면 IT 담당자에게 요청 |
| **`AADSTS50020` / `AADSTS700016`** (계정을 찾을 수 없음) | 다른 테넌트 계정으로 로그인함 | 로그인 화면에서 **회사 계정**을 선택. 그래도 안 되면 `MS_OAUTH_TENANT` 를 회사 테넌트 ID 로 지정 |
| **`AADSTS7000218` / client_secret 이 필요하다는 오류** | 등록이 "웹" 플랫폼으로 되어 있음 | STEP 3 을 **모바일 및 데스크톱 애플리케이션** 으로 다시 추가. "웹" 플랫폼이 있으면 삭제 |
| **`AADSTS9002346` — 개인 Microsoft 계정 전용으로 구성됨** | 앱 등록의 계정 유형이 `개인 Microsoft 계정만` | `관리 → 매니페스트` 에서 `"signInAudience"` 를 **`"AzureADMyOrg"`** 로 바꾸고 저장 (개인 계정도 함께 쓰려면 `"AzureADandPersonalMicrosoftAccount"`). 앱 재빌드는 불필요 |
| **`AADSTS9002346` 이 값을 바꿔도 계속 남음** | 앱이 회사 테넌트가 아니라 개인 계정 테넌트에 등록됨 | 포털 오른쪽 위 프로필에서 **회사 계정**으로 로그인된 상태인지 확인 후, 아니면 STEP 1 부터 다시 등록 |
| **인증 화면에 `+ 플랫폼 추가` 버튼이 안 보임** | 창이 좁아 잘림 / 엔터프라이즈 애플리케이션 화면 / 권한 부족 | 창 최대화 후 아래로 스크롤 → 그래도 없으면 STEP 3 **방법 B(매니페스트)** 로 진행 |
| 브라우저 동의는 끝났는데 **앱이 계속 "연결 안 됨"** | 브라우저가 로컬 포트로 못 돌아옴 | 보안 프로그램/VPN 이 localhost 를 막는지 확인. 앱을 껐다 켜고 다시 시도 |
| Android 에서 **`연결`을 눌러도 브라우저가 안 열림** | 옛 APK | `flutter clean` 후 `make build-apk` → `flutter install` 로 재설치 |
| 연결은 됐는데 **가져올 캘린더가 비어 있음** | 첫 연결 시 목록 조회 실패 | 화면을 나갔다 다시 들어오거나 **`재시도`** 를 누름. 그래도 안 되면 **`연결 해제`** 후 다시 연결 |
| 할 일은 만들어지는데 **캘린더에 안 올라감** | 그 할 일에 **날짜가 없음** | 날짜가 있는 할 일만 캘린더로 나갑니다. 메모(note) 타입도 제외됩니다 |
| Outlook 에서 **완료 표시가 안 보임** | 의도된 동작 | Outlook 은 일정 단위 색 지정이 별도 등록을 요구해 이번 범위에서 제외했습니다. 구글은 회색으로 표시됩니다 |
| **모든 할 일 동기화가 갑자기 멈춤** (기기 간 반영 안 됨) | STEP 6 을 건너뜀 (`PGRST204`) | STEP 6 을 실행하십시오 |

## 연결을 끊고 싶을 때

앱의 **설정 → Microsoft 365 → `연결 해제`** 를 누르면 됩니다. 캘린더 선택과 카테고리 매핑은 그대로 남아 다시 연결하면 복원됩니다. Microsoft 쪽 대기 중인 작업만 정리되고 **구글 연동은 영향을 받지 않습니다.**

Azure 쪽에서 완전히 지우시려면 포털의 앱 등록 화면에서 **`삭제`** 를 누르시면 됩니다.
