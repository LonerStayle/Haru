## 1. 요약

- **방향 전환 한 줄**: "하루 앱이 구독을 끌어다 쓴다" 가 아니라 **"대표님이 이미 여는 Claude Code / Claude 앱이 하루 데이터를 도구로 부른다"** 입니다. 약관·비용·앱 코드 세 축이 모두 이 방향에서만 깨끗합니다.
- **9-25 기각 사유 재점검**: 사유 5(API 종량 과금)는 구독으로 사라집니다. 사유 1(하루 2~3건 규모)은 "건별 자동 판정" 대신 **"월·주 단위 묶음 처리"** 또는 **"이미 진행 중인 개발 세션"** 을 입력으로 삼으면 피해 갈 수 있습니다. 사유 3(회사 제목 전송)은 work 카테고리를 기본 제외하는 정책으로 막습니다.
- **추천 순서**: ① Claude Code `/haru 마감` (git × 개인개발 대조) → ② 월 1회 백로그 대청소 대화 → ③ 비정형 텍스트 → 받은함 캡처 → ④ 장기목표·아이디어 다듬기. 네 가지 모두 **1단계는 Claude Code skill 하나로, Dart 코드 0줄·서버 0개**로 시작합니다.
- **원격 MCP 커넥터(Claude Android 앱 직접 사용)와 제안함 테이블**은 2주 시험 운행에서 실제 호출 실적이 나온 뒤 2단계로 결정합니다.
- **하지 말 것 3건**: 앱 안에서 `claude -p` / `codex exec` 호출, 풀 CRUD MCP 또는 Routine 에 쓰기 권한, 구독 자격증명 서버 보관(SIWC 내장 포함).
- ChatGPT 구독은 현재 **보조**입니다. Plus 에서 MCP 쓰기가 되는지, SIWC 가 비공개 앱을 받는지 실계정 확인 전까지는 `.agents/skills` 공유로 codex 대화형 세션에서 같은 skill 을 쓰는 정도만 권합니다.

### 2-3. 하루 쪽 공통 함정 (어느 경로든 외부에서 쓸 때)

- Realtime 수신은 `CalendarAwareTodoRepository` 를 지나지 않습니다 → 외부에서 `due_at` 을 넣거나 지우면 Google/MS 캘린더와 어긋납니다. **외부 쓰기는 날짜 없음·캘린더 미연결 행만.**
- 반복 4개 컬럼은 `_toRow`/`_fromRow` 에 없음 → 외부에서 반복 생성 금지.
- `updated_at=now()` (UTC ISO) 필수(LWW). 없는 category id 는 '기타'로 복원. 이동 시 하위 항목 category 연쇄(`MovePolicy.descendants`). sort_order 는 형제 최소값−1 외에 건드리지 않음(순서는 명시적 조작으로만).
- Supabase MCP 플러그인의 SQL 실행은 RLS 를 거치지 않을 수 있습니다 → `user_id` 고정을 skill 규칙에 박거나, anon 키 + 대표님 JWT 로 PostgREST 를 부르는 작은 스크립트를 씁니다.

## 3. Top 추천 (해볼 만한 것)

공통 전제: 1단계는 저장소 `.claude/skills/haru/` (+ `.agents/skills/haru/` 복제로 codex 공유) **skill 하나**. 쓰기는 항상 **미리보기 표 → 대표님 "확정" → 반영 → `docs/ai/haru-skill-log.jsonl` 기록(되돌리기용)**. work 카테고리는 기본 제외. 앱 UI 변경이 없으므로 macOS/Android parity 원칙과 충돌하지 않고, 결과는 Realtime 으로 양쪽에 들어갑니다. Android 입력은 Remote Control 로 대신합니다.

### T1. `/haru 마감` — Claude Code 세션 끝에 git × 개인개발 대조 + 남은 일 인계 (병합: 5, 8, 10, 20)

- **왜**: 대표님은 Claude Code 를 매일 쓰고, 개인개발 할 일의 실제 진척은 커밋에 남습니다. 커밋 메시지("fix(shell): 좁은 데스크탑 창에서…")와 할 일 제목("좁은 창 상세 깨짐")을 의미로 맞추는 건 문자열 규칙으로 안 됩니다. 입력이 이미 세션 안에 있어 **추가 외부 전송이 없고**, 개인 저장소·개인개발 카테고리만 다룹니다. 9-25 의 B6(끝났을 가능성)이 약했던 이유(근거 데이터 없음)를 git 이 채웁니다.
- **첫 단계 범위**: `git log --since=midnight` 과 personal_dev 미완료 목록을 대조해 "완료 후보(근거 커밋 표시, 기본 선택 해제)" 와 "이번 세션 남은 일 → 부모 1건 + 설명 `- [ ]` 목록" 을 미리보기로 제시합니다. 쓰기는 `done_at`+`updated_at` 만(날짜·캘린더 없는 행 한정)과 insert 1건만 허용합니다. 설명 목록은 기존 `DescriptionChecklist` 가 하위 항목으로 바꿔 주므로 새 UI 가 필요 없습니다.

### T2. 월 1회 백로그 대청소 대화 (병합: 3, 15, 19, 23)

- **왜**: 대표님 데이터의 몸통은 날짜 없는 카테고리 백로그입니다. 9-25 기각 사유 2(오늘 화면이 비어 있음)가 여기서는 오히려 근거가 됩니다. 한 번에 수십~수백 건을 다루므로 사유 1(규모)에도 걸리지 않습니다. `StaleBacklogPolicy` 는 "오래됨" 까지만 압니다. "같은 일 묶음", "이미 끝난 듯", "장기 목표로 올릴 성격", "막연해서 손이 안 가는 제목 → 다음 행동으로 재작성" 은 의미 판단입니다.
- **첫 단계 범위**: 1~2회차는 **읽기 전용**입니다. 미완료·무날짜 항목을 카테고리별로 읽어 묶음 리포트만 내고, 반영은 대표님이 앱에서 직접 합니다. 실효가 확인되면 `mark_done(ids)` 같은 좁은 쓰기 하나만 추가합니다. 이동·병합·삭제는 끝까지 도구로 만들지 않습니다(9-25 D2 "위험 최대" 결론 유지).

### T3. 비정형 텍스트 → 하루 '받은함' 캡처 (병합: 1, 21, 22 / 9-25 A7 재검토)

- **왜**: 회의록·메일·긴 대화에서 할 일 단위를 잘라내는 건 `splitBulkLines`(줄 단위)로 안 됩니다. 9-25 의 A7 기각 사유였던 API 비용과 새 전송 경로는 "이미 열려 있는 Claude 세션" 이 입력 창구가 되면서 사라집니다. 한 줄 추가는 지금처럼 ⌘⇧N 이 맡고, AI 는 **긴 비정형 입력을 받을 때만** 대표님이 직접 부릅니다.
- **첫 단계 범위**: 대표님이 앱에서 '📥 받은함' 카테고리를 한 번 만들고(id 고정), skill 의 `/haru add` 는 그 카테고리에만 insert 합니다(제목+설명만, 날짜·부모·반복 없음). 분류와 이동은 대표님 손으로 합니다. 쓰기 표면이 "받은함에 추가" 뿐이라, 붙여넣은 메일 속 인젝션이 성공해도 피해는 "이상한 항목 몇 개" 로 묶입니다. 갤럭시 사진·스크린샷 입력(원격 커넥터)은 2단계입니다.

### T4. 장기 목표·아이디어 다듬기 (병합: 6, 18)

- **왜**: 장기 목표와 개인 아이디어 카테고리는 적고 나면 다시 손대지 않는 곳이 되기 쉽습니다. 막연한 목표는 목록을 못 적어서 머물러 있으므로, 질문으로 구체화해 **대표님 습관(설명에 목록)** 형태로 돌려주면 기존 규칙이 이어받습니다. 회사 정보가 아니라 전송 부담이 가장 적은 영역입니다.
- **첫 단계 범위**: longterm·idea 카테고리만 노출하고, 쓰기는 **설명 끝에 날짜 머리 + 구분선 붙여 append** 하나만 허용합니다. 쓰기 직전 `updated_at` 을 다시 읽어 바뀌었으면 중단합니다(LWW 로 앱 편집분이 덮이는 것 방지). 요약 블록은 800자 상한을 둡니다.

### 단계 0 (위 4개 공통 착수 조건): 2주 시험 운행 + 오프라인 벤치마크

- skill 을 만들기 전에 Claude Code 세션에서 실제 DB 를 **읽기 전용**으로 붙여 T1~T4 를 수동으로 2주 써 보고, 호출 횟수를 셉니다. 기준(예: 2주에 T1 5회 이상)을 못 넘으면 접습니다.
- 메모리 지시("AI 를 다시 꺼내면 먼저 앱 밖 오프라인 벤치마크")에 따라, 같은 기간에 **제목→카테고리 281건 벤치마크**도 Claude Code 세션(구독, 0원)에서 한 번 돌립니다. T3 에서 Claude 가 제안하는 카테고리의 품질 근거로 그대로 쓸 수 있습니다.
