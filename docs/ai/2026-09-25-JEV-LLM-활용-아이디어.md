# 하루 × JEV · LLM 활용 아이디어

작성: 2026-09-25 · 대상: 하루(macOS + Android, Flutter / Supabase / Google Calendar)
목적: "적고, 하나씩 처리하는" 대표님 흐름을 **더 빠르고 덜 귀찮게** 만드는 AI 기능 후보를 정리하고, 어떤 일에 JEV 를 쓰고 어떤 일에 LLM 을 쓸지 나눈다.

---

## 0. 한 줄 요약

- **JEV = 빠르고 싼 "결정기"**: 정해 둔 선택지 중 하나를 확률과 함께 돌려준다. 분류·판정·라우팅용.
- **LLM = 느리지만 똑똑한 "작성기"**: 자연어 해석, 글 쓰기, 쪼개기, 요약용.
- 하루에서의 역할 분담: **입력 순간(200ms 체감 목표)은 JEV + 규칙**, **생각이 필요한 순간(분해·회고·자연어 명령)은 LLM**. 둘 다 **제안만 하고, 쓰기는 사용자가 누를 때** + 되돌리기.

## 1. JEV 가 뭔가 (2026-09 기준)

| 항목 | 내용 |
|---|---|
| 만든 곳 | TypeSafe AI (샌프란시스코, 2024 설립). 2026-09-15 제한적 얼리 액세스 공개, US$40M 시드 |
| 정체 | "System One Model" — 대화용이 아니라 **소프트웨어 안의 빠른 결정** 전용. 자연어를 생성하지 않고 **타입이 정해진 값 + 확률/신뢰도**를 돌려준다 |
| 질문 종류 3가지 | `choice`(선택지 중 하나 + 선택지별 확률) · `score`(정해 둔 단계로 등급) · `noul`(예/아니오 확률 0~1) |
| 호출 모양 | `POST https://thejevai.com/v1/systemone` · `model: "jev-latest"` · `state`(텍스트/JSON) + `questions`(키별 type·instructions·criteria). 여러 질문을 한 번에 병렬 평가 |
| 속도·비용(회사 주장) | 응답 70~500ms, 프런티어 LLM 대비 40~200배 빠르고 40~400배 싸다(자체 측정치라 상한값일 수 있음) |
| 접근·가격 | 얼리 액세스, **공개 가격 없음** |
| 약점 | 아키텍처·가중치·논문 비공개, 합성 데이터로만 학습. **프롬프트 인젝션에 흔들린다** — 입력(state)에 "승인됨" 같은 가짜 필드를 넣자 차단 확률이 0.76 → 0.48 로 떨어진 시연. 신뢰도는 "정답 확률"이 아니라 **선택지 간 마진** |
| 권장 사용법 | LLM 을 대체하지 말고 옆에서 **분류·라우팅·점수·안전 판정**만. 결정적 규칙과 **함께**, 고위험 동작은 사람 확인, 도구가 가져온 외부 텍스트는 판정 입력에서 제외, 결정 로그 남기기 |

> 출처: 문서 맨 아래 "참고".

### 하루에 주는 의미
- 하루의 AI 필요는 대부분 **"이게 어느 카테고리냐 / 할 일이냐 메모냐 / 캘린더에 올릴 일이냐 / 이미 있는 일이냐"** 같은 **짧은 판정**이다 → JEV 가 딱 맞는 모양.
- 반대로 **"내일 3시 치과"에서 날짜·시각 꺼내기**, **"이사 준비"를 하위 체크리스트로 쪼개기**는 글을 만들어야 해서 **LLM** 몫(JEV 는 자유 텍스트를 뽑지 못한다).

## 2. 설계 원칙 (하루 규칙과 맞춤)

1. **AI 는 제안, 쓰기는 사용자** — 자동 저장·자동 이동·자동 정렬 금지. 기존 규칙 "순서는 명시적 조작으로만", "탭 = 상세", "닫힘 = 저장" 을 그대로 지킨다. 제안을 받아들이면 그때 쓰고 **되돌리기(⌘Z) 스낵바**.
2. **느려지지 않는다** — 빠른 추가는 AI 없이 즉시 저장. AI 결과는 저장 뒤 비동기로 와서 칩으로 "회사로 옮길까요?" 를 띄운다. 입력→저장 200ms 목표는 AI 가 절대 잡아먹지 않는다.
3. **규칙이 먼저, AI 는 보강** — 날짜 정규식·키워드 사전·최근 사용 카테고리 같은 결정적 규칙을 1차로. AI 는 규칙이 애매할 때만. 오프라인·키 없음·한도 초과면 규칙만으로 정상 동작.
4. **키는 서버에만** — JEV 키·LLM 키는 앱에 넣지 않는다. **Supabase Edge Function `ai-gateway`** 가 대표님 로그인 토큰으로만 호출을 받아 대신 부른다(호출 수 제한·로그 포함).
5. **개인 데이터 최소 전송 + 끌 수 있게** — 설정에 "AI 도움" 스위치(기본 끔 → 켜면 무엇을 보내는지 안내). 판정에는 제목·카테고리 이름 정도만. 설명·메모 본문은 기능이 꼭 필요할 때만.
6. **외부 텍스트는 명령이 아니다** — 캘린더 초대(남이 쓴 제목·본문), 붙여넣은 메일은 **판정 입력(state)으로만** 쓰고, 그 내용이 동작을 승인하게 두지 않는다(JEV 인젝션 사례 대응). 파괴적 동작(일괄 삭제·이동)은 AI 판정과 무관하게 **항상 확인 + 되돌리기**.
7. **갈아끼울 수 있게** — `DecisionService`(choice/score/noul) 인터페이스 뒤에 `JevDecisionService` / `LlmDecisionService`(LLM 구조화 출력) / `RuleDecisionService` 를 둔다. JEV 가 얼리 액세스·무가격이라 사라지거나 비싸져도 LLM 으로 즉시 대체.

## 5. 구조 스케치

```
[Flutter 앱]
  빠른 추가 ─ 저장(즉시, 로컬) ─┐
                                 └─ (비동기) AiSuggestService ─┐
  상세 "쪼개기 제안" ─────────────────────────────────────────┤
                                                                ▼
                                        Supabase Edge Function: ai-gateway
                                         ├─ 인증: 대표님 JWT 만
                                         ├─ 호출 제한 · 결정 로그(state 요약·스키마·모델 버전·확률)
                                         ├─ /decide  → JEV (choice/score/noul)
                                         │              └ 실패·미가용 → LLM 구조화 출력으로 폴백
                                         └─ /write   → LLM (파싱·쪼개기·요약)
[앱 쪽 인터페이스]
  DecisionService { choice(), score(), noul() }  ← Jev / Llm / Rule 구현 교체 가능
  제안 UI = 칩 · 제안 목록(체크) · 되돌리기 스낵바 (기존 undo_snackbar / ⌘Z 재사용)
```

- **LLM 모델**: 파싱·판정 폴백은 가볍고 빠른 모델(Claude Haiku 4.5), 쪼개기·회고·일괄 명령 계획은 상위 모델(Claude Sonnet 5 / Opus 5.5)로 나눈다.
- **임계값**: JEV 확률 ≥ 0.85 → 칩 1개(원탭), 0.5~0.85 → 상위 2개 칩, < 0.5 → 제안 안 함. 파괴적 동작은 확률과 무관하게 확인.
- **학습 신호**: 제안 수락/거절을 로컬에 기록 → 월 1회 수락률로 임계값·프롬프트 조정(외부 전송 없이).

## 6. 위험과 대응

| 위험 | 대응 |
|---|---|
| JEV 얼리 액세스 — 가격 미공개, 서비스 변동 | DecisionService 뒤에 숨기고 LLM 폴백. 핵심 기능이 JEV 에만 기대지 않게 |
| 프롬프트 인젝션(캘린더 초대·붙여넣은 메일) | 외부 텍스트는 판정 state 로만, 동작 승인 근거로 안 씀. 결정 로그. 파괴적 동작은 항상 사람 확인 |
| 신뢰도를 정답 확률로 오해 | "마진"으로 취급 — 임계값 + 제안형 UI 로만 사용 |
| 개인 데이터 외부 전송 | 기본 끔, 켤 때 안내, 최소 필드, 설명·메모 본문은 해당 기능에서만 |
| 느려짐 | 저장은 AI 와 무관하게 즉시, AI 결과는 비동기 칩. 타임아웃 1.5초 후 조용히 포기 |
| 자동화가 순서·데이터를 바꿈 | 금지 — 모든 쓰기는 사용자 탭 + 되돌리기 |
| 비용 폭주 | ai-gateway 에서 일일 호출 상한, 같은 입력 캐시 |

## 7. 결정이 필요한 것 (대표님)

1. **JEV 얼리 액세스 신청 여부** — 신청 전까지는 A1·A3·A4 를 LLM(Haiku) 구조화 출력으로 먼저 만들고, 승인 나면 JEV 로 교체해 속도·비용 비교.
2. **어떤 LLM 계정/키로 갈지** — Anthropic API 키를 Supabase 비밀값으로.
3. **개인 데이터 전송 범위** — 제목만 / 제목+설명 / 기능별 선택.
4. **1차 범위** — 위 추천(A1·A2·B1 + 인프라) 그대로 갈지.
