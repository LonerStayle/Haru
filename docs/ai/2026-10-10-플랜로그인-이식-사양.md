### A.2 동적 client 등록과 host id

- **host id** — [코드] `SiwcAccountStore.hostId()`: `ext_agent_host_id = "urn:uuid:<UUIDv4>"`. 기기(host)마다 1회 만들어 영구 저장. 없으면 authorize URL 을 만들지 않는다(`require(hostId.isNotBlank())`).
- **첫 등록** — `client_id=dynamic_agent_client` + `agent_name_hint` + `ext_agent_host_id`. 사용자가 브라우저에서 에이전트 이름을 정하고 승인하면 **콜백 쿼리에 발급 `client_id`** 가 온다. 이 값을 저장하고 코드 교환·갱신·revoke·재로그인에 쓴다 [공식 "Registration and sign-in"].
- **부수 효과** [실측 §1]: 새 등록마다 ChatGPT 설정 → App limits 에 항목이 하나씩 생긴다. 같은 계정 재로그인은 **저장한 발급 client_id 로 재인가**해야 항목이 늘지 않는다.
- **[하루]** macOS 와 Android 는 서로 다른 host 다 → host id·발급 client_id 가 기기마다 따로 생기고 App limits 에 항목이 2개가 된다(정상). 기기 간에 토큰을 Supabase 로 공유하지 않는다.

### A.3 로그인 모드 4종 — [코드] `A/data/auth/AuthorizeUrl.kt`, `SiwcLoginCoordinator.startOptionsOf`

| 모드 | 요청 client_id | 추가 파라미터 | 언제 |
|---|---|---|---|
| NewAccount | `dynamic_agent_client` | `agent_name_hint` | 저장 계정 없음 / 저장 계정이 `invalid_client` 로 NEEDS_REAUTH |
| Reauth | 저장 client_id | `id_token_hint`(보관 시), `login_hint`(=저장 email, 보관 시) | 저장 계정 있음 + planUsage=true |
| Reconsent | 저장 client_id | Reauth 와 같음 + `prompt=consent` | 저장 계정 planUsage=false ("다시 허용하기") |
| PendingRetry | PENDING 레코드의 발급 client_id | 없음 (hint·agent_name_hint·prompt 모두 없음) | 새 등록 콜백에서 client_id 는 받았는데 교환·검증이 실패해 PENDING 이 남음 |

시작 모드 규칙(`startOptionsOf`): (a) 저장 레코드(PENDING 제외) 0개 → NewAccount, 단 PENDING 이 있으면 가장 최근 PENDING 으로 PendingRetry. (b) 1개 이상 → active(없으면 savedAt 최신)로 Reauth. (c) 그 레코드가 planUsage=false → Reconsent. 추가: 그 레코드의 needsReauthReason == `INVALID_CLIENT` → NewAccount.

[실측 §6f L1] Reauth 는 계정 선택은 건너뛰지만 **동의 화면("Connect … to ChatGPT" Continue)은 다시 뜬다** → 무인 재인가 불가, 재로그인은 늘 사람 1클릭.

### A.4 authorize URL — 파라미터 순서·인코딩

[코드] `AuthorizeUrl.params` 가 만드는 **순서 그대로**:

```
client_id            = <모드별>
agent_name_hint      = <AGENT_NAME>          # NewAccount 만
ext_agent_host_id    = urn:uuid:<uuid>
response_type        = code
redirect_uri         = http://127.0.0.1:<port>/auth/callback
scope                = openid profile email offline_access resource.invoke chatgpt.tokens.use.direct
resource             = https://api.openai.com/v1
state                = <32바이트 랜덤 base64url 무패딩>
nonce                = <32바이트 랜덤 base64url 무패딩>
code_challenge_method= S256
code_challenge       = base64url(sha256(ascii(verifier))) 무패딩
id_token_hint        = <저장 id_token>       # Reauth·Reconsent 이고 값이 있을 때만
login_hint           = <저장 email>          # Reauth·Reconsent 이고 값이 있을 때만
prompt               = consent               # Reconsent 만
```

인코딩 [코드] `AuthorizeUrl.encode`: **RFC 3986** — `A-Z a-z 0-9 - . _ ~` 만 그대로, 나머지는 UTF-8 바이트마다 `%XX`(대문자 hex). **공백은 `%20`**. key 와 value 모두 인코딩하고 `&` 로 잇는다. 결과 = `AUTHORIZE_URL + "?" + query`.

> ⚠️ **Dart 함정 (확인함)**: `Uri.replace(queryParameters: …)` 는 공백을 `+` 로 만든다 (`scope=openid+profile`). Andy 와 같은 바이트를 내려면 Andy 의 `encode` 를 Dart 로 그대로 옮긴 함수로 쿼리를 직접 조립한다.

> ⚠️ URL 에 `id_token_hint`(id token)가 들어갈 수 있다 — 로그·예외 메시지 금지.

### A.6 loopback 콜백 서버 — [코드] `A/data/auth/LoopbackCallbackServer.kt`

**bind**: `127.0.0.1` 에만 (0.0.0.0 금지). 선호 포트 1455 → 실패하면 포트 0(임의). 실제 포트로 `redirect_uri` 를 만든다. **브라우저를 열기 전에** bind 한다.

**요청 처리 규칙 (시도는 끝까지 계속 기다린다 — 다른 앱·favicon 요청이 시도를 끝내지 못하게)**

| 조건 | 응답 | 시도 |
|---|---|---|
| 요청 줄이 `METHOD TARGET HTTP/x` 3토큰이 아님 | 400 | 계속 대기 |
| 경로(`?` 앞)가 `/auth/callback` 아님 | 404 (`LOGIN stray_request status=404`) | 계속 대기 [실측 §6f: 콜백 뒤 404 1건 정상] |
| 메서드가 GET 아님 | 405 | 계속 대기 |
| 이미 결과를 받음 | 409 | 계속 대기 |
| 쿼리 파싱 실패 / `state`·`code`·`client_id`·`error` 중 하나가 **두 번** 나옴 / state 없음 / state 불일치(상수 시간 비교) | 400 | 계속 대기 |

- 붙잡은 응답은 30초 안에 결과를 못 내면 ERROR 페이지를 자동으로 보낸다. 서버를 닫을 때 아직 응답 못 한 연결에도 ERROR 페이지.

  Content-Type: text/html; charset=utf-8        (상태 응답은 text/plain; charset=utf-8, 본문 "<status> <reason>\n")
  Content-Length: <n>
  Cache-Control: no-store
  Referrer-Policy: no-referrer

### A.7 콜백 처리 순서 — [코드] `SiwcLoginCoordinator.attemptFlow` / `handleCallback`

1. 저장소 읽기 → host id 확보(없으면 생성·저장, 저장 실패 → STORE_WRITE_FAILED).
2. 모드별 대상 계정 확인(Reauth·Reconsent 인데 레코드 없음 → NO_ACCOUNT). 대상 계정이 SIGNING_OUT 이면 시작 안 함(SIGNING_OUT).
3. PKCE 생성 → 서버 bind(실패 → LISTENER_FAILED) → redirect_uri → authorize URL → 브라우저 열기(실패 → BROWSER_UNAVAILABLE).
4. 콜백 대기 (전체 10분 타임아웃 → TIMEOUT).
5. 콜백 파라미터:
   - `error` (비어 있지 않으면), `client_id` (비어 있지 않으면), `code`.
   - **NewAccount**: 발급 client_id = 콜백 `client_id` 가 `dynamic_agent_client` 가 아니고 정규식 `[A-Za-z0-9_.\-]{1,200}` 에 맞을 때. 있으면 **교환 전에** PENDING_REGISTRATION 레코드로 저장(이미 있으면 그대로)하고 재시도 모드를 PendingRetry(issued) 로 바꾼다. 그다음 `error` 가 있으면 authorize 오류, 발급 client_id 가 없으면 REGISTRATION_INCOMPLETE.
   - **그 밖 모드**: 콜백 `client_id` 가 있으면 저장값과 같아야 함(다르면 CLIENT_MISMATCH, 덮어쓰지 않음). 재인가 콜백은 `client_id` 를 생략할 수 있다. 그다음 `error` 처리.
   - `error == "access_denied"` → DENIED (페이지 DENIED). 그 밖 error → AUTHORIZE_ERROR (로그에는 `[a-z_]{1,64}` 에 맞을 때만 값).
   - `code` 없음 → MISSING_CODE.
6. 코드 교환(A.8). 실패 분류: CLIENT + `invalid_grant` → EXCHANGE_REJECTED (code 버리고 새 인가, PENDING 유지) / NETWORK / SERVER(5xx) / 그 밖 EXCHANGE_FAILED.
7. `id_token` 없음 → ID_TOKEN_INVALID. 검증(A.9) 실패 → ID_TOKEN_INVALID (JWKS 못 받음은 NETWORK).
8. 재인가면 새 id_token 의 `sub` 가 저장 subject 와 같아야 함(다르면 ACCOUNT_MISMATCH, 덮어쓰지 않음).
9. `planUsage = "chatgpt.tokens.use.direct" ∈ scopes`.
10. **한 번의 원자적 저장**으로 레코드 교체 + active 지정: clientId, subject, email(claims.email ?: 기존), idToken, accessToken, refreshToken, expiresAt, earliestRefreshAt, scopes, savedAt, createdAt(기존 유지), authorizationEpoch+1, planUsage, state=SIGNED_IN, needsReauthReason=null. 저장 직전에도 기존 subject 와 다르면 ACCOUNT_MISMATCH.
11. 결과 페이지 응답(planUsage → OK, 아니면 DENIED), 앱을 앞으로(Android, 실패해도 무시).

실패 사유 enum 전체: `DENIED, AUTHORIZE_ERROR, REGISTRATION_INCOMPLETE, CLIENT_MISMATCH, MISSING_CODE, EXCHANGE_REJECTED, EXCHANGE_FAILED, NETWORK, SERVER, ID_TOKEN_INVALID, ACCOUNT_MISMATCH, TIMEOUT, BROWSER_UNAVAILABLE, LISTENER_FAILED, NO_ACCOUNT, SIGNING_OUT, STORE_WRITE_FAILED, INTERNAL`.

한 번에 한 시도만: 진행 중에 `start` 하면 기존 시도를 취소(비밀 폐기, 포트 해제).

### A.8 토큰 엔드포인트 — [코드] `A/data/auth/TokenEndpoint.kt`

공통: `POST https://auth.openai.com/api/accounts/oauth/token`, 헤더 `Accept: application/json`, 본문 **form-urlencoded**, client secret 없음(공개 클라이언트). 리다이렉트 따르지 않음(3xx 는 실패). 타임아웃: connect 15s / read 20s / write 15s / call 30s (`SiwcHttp.kt`).

**코드 교환** (form 필드 순서대로)
```
grant_type    = authorization_code
client_id     = <발급 client_id>
code          = <콜백 code>
code_verifier = <verifier>
redirect_uri  = <authorize 에 보낸 것과 바이트까지 같은 값>
resource      = https://api.openai.com/v1
```

**갱신** — scope 는 보내지 않는다(기존 grant 유지). 성공하면 refresh 도 **회전**한다 [실측 R6].
```
grant_type    = refresh_token
client_id     = <발급 client_id>
refresh_token = <refresh token>
resource      = https://api.openai.com/v1
```

**revoke (로그아웃)** — 주소 = discovery `revocation_endpoint` (실패 시 `https://auth.openai.com/api/accounts/oauth/revoke`)
```
token           = <refresh token>
token_type_hint = refresh_token
client_id       = <발급 client_id>
```
200 = 성공(이미 무효인 토큰도 200 [공식]) / 5xx·네트워크 = 재시도 대상 / 그 밖 = 거절.

**성공 응답 파싱** (200 + JSON object + `access_token` 비어 있지 않음, 아니면 MALFORMED)
- `access_token`, `refresh_token`(빈 값 → null), `id_token`(빈 값 → null), `expires_in`(정수/실수/문자열 모두 허용), `scope`(공백 구분), `earliest_refresh_at`(서버 기준 **절대 Unix 초**), 응답 `Date` 헤더(ms), 받은 시각(ms).
- 실측 응답 키 [실측 R6]: `access_token, earliest_refresh_at, expires_in(3600), id_token, refresh_token, scope, token_type`. `earliest_refresh_at` ≈ 발급 + 54분.
- 갱신 응답에 없는 필드(id_token·scope·refresh_token)는 **이전 값 유지**. scope 가 오면 planUsage 재계산 (`refreshedWith`).

**실패 응답 분류**: 네트워크 예외 → NETWORK / 5xx → SERVER / 그 밖 비성공 → CLIENT(code 로 terminal 여부 판정) / 200 인데 깨짐 → MALFORMED.
오류 code 추출(`errorCode`): `{"error":"invalid_grant"}` 또는 `{"error":{"code"|"type"}}` 또는 `{"code"}` 중 정규식 `[A-Za-z0-9_.:\-]{1,100}` 에 맞는 값만.

**시각 계산** — [코드] `TokenTiming` (`SiwcAccount.kt`)
```
expiresAt        = receivedAt + (expires_in > 0 ? expires_in : 3600) * 1000
earliestRefresh  = earliest_refresh_at 없음/≤0 → 0
                   serverNow = Date 헤더 ?: access_token JWT 의 iat*1000 ?: receivedAt
                   derived   = receivedAt + (earliest_refresh_at*1000 − serverNow)
                   derived > expiresAt → expiresAt − 5분, 아니면 derived
refreshAt        = max(earliestRefresh, expiresAt − 5분)
needsRefresh     = access 없음 || now ≥ expiresAt || now ≥ refreshAt
```
[실측 R6] earliest 는 강제가 아니다(418초 전에 갱신해도 200). 401 이면 언제든 갱신해도 된다.

### A.9 id_token 검증 — [코드] `A/data/auth/IdTokenVerifier.kt`

순서: 헤더 `alg == "RS256"`(none·HS256 거부) → JWKS 에서 `kid` 로 키 선택(캐시에 없으면 1회 재조회, kid 없으면 키가 하나일 때만) → RS256 서명 → `iss == "https://auth.openai.com"` → `aud`(문자열 또는 배열) ∋ 발급 client_id → `azp` 가 있으면 == client_id, aud 가 2개 이상이면 azp 필수 → `exp` 필수 && `now/1000 ≤ exp + 60` → `nonce` 필수 && 상수 시간 비교로 일치 → `sub` 필수(비어 있지 않음). 결과 = (sub, email, exp).
JWKS 파싱: `kty=RSA`, `use` 없거나 `sig`, `alg` 없거나 `RS256`, `n`·`e` 있음, 모듈러스 ≥ 2048비트만.

하루의 생략 판단은 §C.8.

### A.10 계정 레코드 — [코드] `A/data/auth/SiwcAccount.kt`

저장 파일(JSON, schema=1): `{ "schema":1, "active":"<clientId>|null", "accounts":[record…] }` + 별도 host id.
record 필드: `clientId, subject, email, idToken, accessToken, refreshToken, expiresAtMs, earliestRefreshAtMs, scopes[], savedAtMs, createdAtMs, planUsage, state, needsReauthReason, authorizationEpoch`.

### A.11 자격 공급·갱신·401 — [코드] `A/data/auth/SiwcCredentialProvider.kt`

`current()`:
1. 활성 레코드 없음 → AuthRequired(SIGNED_OUT).
2. 사용 가능 판정 `ensureUsable`: SIGNING_OUT → AuthRequired(SIGNING_OUT) / SIGNED_OUT·PENDING → SIGNED_OUT / NEEDS_REAUTH → NEEDS_REAUTH(사유) / SIGNED_IN 인데 planUsage=false → **PLAN_SCOPE_MISSING** (추론 금지, "다시 허용하기").
3. `needsRefresh` 아니면 access 반환. 선갱신 실패 백오프(30초) 중이고 access 아직 유효하면 access 반환.
4. 갱신(single-flight, 계정별 락 + 락 대기 중 끝난 시도의 결과 공유). **호출자가 취소돼도 갱신 요청·저장은 끝까지**(회전된 refresh 를 버리면 다음 갱신이 `refresh_token_reused` → 계열 무효화).
5. 선갱신이 비-terminal 로 실패해도 access 가 아직 유효하면 그대로 쓴다.

갱신 결과 처리:
| 결과 | 처리 | 던지는 것 |
|---|---|---|
| 성공 | access·refresh(회전)·id·만료·scope·earliest 를 한 번에 저장. 저장 직전 레코드의 refresh 가 우리가 쓴 값과 다르면(그새 재로그인) 저장하지 않고 최신 값 사용. 디스크 쓰기 실패해도 메모리엔 유지 | — |
| CLIENT + terminal 코드 | access·refresh 삭제(idToken 보존) + NEEDS_REAUTH(code) | AuthRequired(NEEDS_REAUTH, code) |
| CLIENT + `invalid_client` | NEEDS_REAUTH(INVALID_CLIENT) (토큰 유지, 다음 로그인은 NewAccount) | AuthRequired(NEEDS_REAUTH, invalid_client) |
| NETWORK | 30초 백오프 | Network (재시도 대상) |
| SERVER(5xx) | 30초 백오프 | Server (재시도 대상) |
| 그 밖 4xx·MALFORMED | 토큰·상태 유지, 30초 백오프 | RefreshDeferred (재시도 금지, 재로그인 안내 없음) |
| refresh 토큰 없음 | 선갱신이면 access 유효한 동안 그대로. 아니면 NEEDS_REAUTH(MISSING_REFRESH_TOKEN) | AuthRequired |

401 흐름 (`OpenAiClient.runAttempts`):
1. 스트림 전 401 (코드 무관) → `refreshAfterUnauthorized(거절된 자격)` 1회 → 같은 body 즉시 재전송 (재시도 횟수·예산 밖).
2. 갱신 성공 뒤 또 401 → `onRejectedAfterRefresh` 신호 + **AuthRejected** (토큰·로그인 상태 유지).
3. 갱신으로 받은 토큰이 성공 응답 없이 **같은 원인(401 error.code)으로 연속 2회** 거절 → NEEDS_REAUTH(UNAUTHORIZED_AFTER_REFRESH) (토큰은 지우지 않음).
4. Authorization 헤더에 넣을 수 없는 문자 → 요청 없이 401 과 같은 흐름.

### A.12 로그아웃 — [코드] `SiwcCredentialProvider.signOut`

① 레코드를 SIGNING_OUT 으로 저장(epoch+1) — 이후 모든 새 요청은 AuthRequired(SIGNING_OUT).
② 그 계정 갱신 락을 잡고 **최신** refresh 로 revoke (네트워크·5xx 는 1·2·4초 백오프 3회).
③ 레코드가 아직 SIGNING_OUT 이고 refresh 가 revoke 한 값(또는 없음)일 때만 토큰 3종 삭제 + SIGNED_OUT. (그새 재로그인이 활성화했으면 건드리지 않음)
④ 결과 `revokeConfirmed=false` 면 "원격 해제를 확인하지 못했어요. ChatGPT 설정에서 앱 연결을 끊을 수 있어요" 안내.
프로세스가 SIGNING_OUT 중에 죽으면 다음 시작 때 이어서 끝낸다.
[공식] OpenAI 는 사용자가 ChatGPT 설정에서 앱 연결을 끊어도 알려주지 않는다 — 요청·갱신이 확인했을 때 재로그인 요청.

**JSON 출력 강제 — Andy 의 방식과 하루 설계**
- Andy 는 **`text.format` 을 쓰지 않는다** (`A/data/memory/MemoryTidier.kt:169` "구조화 출력(`text.format`)은 ResponsesRequest 에 없어 JSON 을 글로 받고 느슨하게 꺼낸다"). 방식: instructions 끝에 "출력은 JSON 하나만, 다른 글 없이:" + 예시 JSON → 응답 텍스트에서 첫 `{` ~ 마지막 `}` 를 잘라 lenient 파싱 → 실패하면 빈 결과(아무것도 안 바꿈).
- `text.format` 은 공식 금지 목록에 없지만 **SIWC 경로에서 실측된 적 없음 [미실측]**.
- **[하루] 설계** — D.2 참조: 1순위 `text.format` json_schema(strict), 400 에서 `param` 이 `text`/`text.format` 이거나 detail 에 `format` 이 있으면 그 프로세스 동안 프롬프트 JSON 모드로 전환해 1회 재요청. 같은 `text` 객체 안에 `verbosity` 와 함께 넣는다:
  ```json
  "text": {"verbosity": "low", "format": {"type": "json_schema", "name": "haru_result", "schema": {…}, "strict": true}}
  ```
  strict 스키마 규칙(Andy `StrictSchema.kt` 와 같은 규칙): 모든 `type:"object"` 에 `additionalProperties:false`, `required` = properties 전체 key, 선택 필드는 `type:[원래,"null"]`, 금지 키워드 `default, allOf, not, if, then, else, minLength, maxLength, oneOf`, 루트 `anyOf` 금지, 루트 type object.

**SSE 파싱** — [코드] `A/data/openai/SseLineReader.kt`
- UTF-8 줄 단위(CRLF/CR/LF 허용). `:` 로 시작 = 주석/keep-alive 무시. `event:`·`id:`·`retry:` 무시 — 분기는 data JSON 의 `type` 으로.
- `data:` 값에서 선행 공백 1개 제거. 한 블록의 여러 `data:` 줄은 `\n` 으로 이음. 빈 줄에서 블록 dispatch, EOF 에 남은 블록도 flush.
- `data: [DONE]` → 종료로 취급(방어).
- JSON 파싱 실패/object 아님 → 길이만 알리고 skip(OpenAI) / Claude 는 실패로 끝냄(B.6).

**코드가 없거나 모를 때 (HTTP 상태)**
| 상태 | 예외 |
|---|---|
| 401 (갱신 1회 뒤에도) | AuthRejected |
| 403 | Forbidden(detail) — "이 지역이나 계정에서 사용할 수 없는 요청이에요." |
| 429 + type `insufficient_quota` 또는 quota code(`credit_balance_exhausted, insufficient_quota, organization_spend_limit_exceeded, project_spend_limit_exceeded, organization_usage_limit_exceeded`) | QuotaExhausted (금지) |
| 429 그 밖 | RateLimited(retryAfter) (재시도) |

**스트림 오류**(`response.failed`/`error`): 코드 표 먼저 → type `insufficient_quota`/quota code → QuotaExhausted, type `rate_limit_error` 또는 code `rate_limit_exceeded|slow_down` → RateLimited, type `server_error` 또는 code `server_error|server_is_overloaded` → Server, param `model` → ModelUnavailable, 그 밖 BadRequest. [공식] 사용량 한도는 스트리밍이 시작된 뒤 `response.failed` 로도 온다.

**Retry-After**: `retry-after-ms` 헤더(ms, 실수 허용) 우선 → `Retry-After`(초, 실수 허용, 또는 RFC1123 HTTP-date → now 와의 차). 음수·파싱 불가 → null.

**마스킹** (`SecretMask.kt`) — 로그·진단 텍스트에 적용, **자르기 전에** 마스킹:
`(?<![A-Za-z0-9])sk-[^\s"',]*` → `[key]` / `eyJ[\w-]+\.[\w-]+\.[\w-]*` → `[jwt]` / `(?i)\bbearer\s+[^\s"',]+` → `Bearer [redacted]` / `(?<![A-Za-z0-9_])(?:rt_|oaiapp_)[A-Za-z0-9_\-]+` → 앞 8자 + `…`.

### A.15 재시도 정책 — [코드] `A/data/openai/RetryPolicy.kt`

### B.3 토큰 교환·갱신 — [코드] `ClaudeOAuthClient.exchange/refresh/token`

`POST https://platform.claude.com/v1/oauth/token`, **`Content-Type: application/json`**, 본문 JSON (필드 순서):

교환
```json
{"grant_type":"authorization_code","code":"<code>","client_id":"9d1c250a-e61b-44d9-88ed-5944d1962f5e",
 "redirect_uri":"https://platform.claude.com/oauth/code/callback","code_verifier":"<verifier>","state":"<state>"}
```
갱신
```json
{"grant_type":"refresh_token","refresh_token":"<refresh>","client_id":"9d1c250a-e61b-44d9-88ed-5944d1962f5e",
 "scope":"<저장 scopes 공백 구분, 비어 있으면 SCOPES 전체>"}
```
응답 파싱:
- `access_token` 비어 있으면 실패(invalid_token). `token_type` 이 있는데 `bearer`(대소문자 무시)가 아니면 실패.
- `expires_in`(초, >0) → `expiresAt = now + expires_in*1000`. 없으면 null(로그인에서는 실패 처리).
- `scope` 공백 분리 집합. `refresh_token`(빈 값 → null, 갱신 응답에 없으면 기존 유지).
- 신원: `account.uuid`, `organization.uuid`.
- 갱신 결과의 account/org uuid 가 기존과 다르면 → 토큰 버리고 `credentialUsable=false` (다른 계정에 배정 금지).
- 갱신 뒤 usable = scopes ⊇ {user:profile, user:inference} && expiresAt != null.
HTTP 실패 분류(`json()`): 400·401·403 → `auth_required` ("Claude 로그인을 다시 진행해 주세요."), 그 밖 → `oauth_http_<code>`, IO → `network`, 본문 1,000,000자 초과·JSON 아님 → `invalid_response`. 타임아웃 call 15s, 리다이렉트 따르지 않음.

**로그아웃**: revoke 호출 없음. 로컬 계정 삭제 + epoch+1 (`ClaudeAccountStore.disconnect`).

| `안녕하세요 오늘 할 일 정리해줘 부탁해요 감사합니다` | `99d` (Python 재구현 값) |
`cch=00000` 은 Aside 에서 관찰된 placeholder 이며 native attestation 이 아니다.

**도구 이름 정규화** (`tools`/`messages`/`restoreToolNames`): 알려진 17개 이름 `Read, Write, Edit, Bash, Grep, Glob, AskUserQuestion, EnterPlanMode, ExitPlanMode, KillShell, NotebookEdit, Skill, Task, TaskOutput, TodoWrite, WebFetch, WebSearch` 와 **대소문자만 다른** 이름이면 그 철자로 바꿔 보내고, 응답 tool_use 이름은 원래 이름으로 되돌린다. 그 밖 이름은 그대로. 대소문자 무시 중복이면 실패. **[하루]** 하루 도구 이름(`haru_result` 등)은 목록과 겹치지 않으므로 변환 없음 — 그래도 함수는 옮긴다.

**바디 — 필드 순서** (`MessagesRequest.toBody`)
```json
{
  "model": "<로그인 때 고른 모델 id>",
  "system": [billing, intro, instructions],
  "tools": [{"name":"…","description":"…","input_schema":{…}}],     // 도구 있을 때만
  "tool_choice": {"type":"auto"},                                  // 도구 있을 때만 (지정 없으면 auto)
  "max_tokens": 8192,
  "stream": true,
  "messages": [{"role":"user","content":[{"type":"text","text":"…"}]}]
}
```
`MessagesRequest.text(role, text)` = `{"role":role,"content":[{"type":"text","text":text}]}`. `thinking`·`temperature` 등은 보내지 않는다. 생성자 검사: model 비어 있지 않음, max_tokens > 0, messages 비어 있지 않음.

### B.7 SSE 파싱 — [코드] `A/data/claude/MessageAccumulator.kt`

같은 SSE 줄 파서(A.13)를 쓰되 **JSON 깨짐 = 즉시 실패**(`malformed_sse`). 프로토콜 위반은 전부 `invalid_stream` 실패("Claude 응답 검증에 실패했어요. 도구를 실행하지 않았어요.").

| 이벤트 `type` | 규칙 |
|---|---|
| `ping` | 무시 |
| `error` | `error.type` 으로 실패. `overloaded_error` 면 재시도 가능 표시 |
| `message_start` | 한 번만. `message.id` 있음, `role=="assistant"`, **`model == 요청 모델`**, `content` 빈 배열. `usage` 기억 |
| `content_block_start` | `index == 지금까지 블록 수`(0부터 연속). 블록 type: `text`(초기 text 가 있으면 즉시 델타로 내보냄) / `tool_use`(id·name 필수) / `thinking` / `redacted_thinking`. 그 밖 type → 실패(`unsupported_block`) |
| `content_block_delta` | 열린 블록에만. `text_delta.text` → **스트림 텍스트 조각** / `input_json_delta.partial_json` 누적 / `thinking_delta.thinking` / `signature_delta.signature`. 그 밖 → 실패 |
| `content_block_stop` | 블록 확정. tool_use 는 누적 JSON 을 파싱해 **JSON object 일 때만** `input` 으로(빈 누적이면 start 의 input). 깨진 인자를 `{}` 로 바꾸지 않는다 |
| `message_delta` | 모든 블록이 닫힌 뒤. `delta`(stop_reason 등) 병합, `usage` 병합 |
| `message_stop` | message_delta 이후, 모든 블록 닫힘 → 종료 |
| 그 밖 | 무시(미래 메타데이터) |

종료 판정(`finish`): message_stop 없이 끝남 → `truncated_stream`. tool_use id 중복 → 실패. `stop_reason`:
- `end_turn`, `stop_sequence` → 완료 (tool_use 블록이 있으면 실패)
- `tool_use` → 완료 (tool_use 블록이 반드시 있어야)
- `max_tokens`, `refusal`, `model_context_window_exceeded` → **불완전**(도구 실행 금지)
- 그 밖 → 실패(`unsupported_stop`)
텍스트 = `text` 블록들의 text 를 순서대로 이음.
usage: input = input_tokens + cache_read_input_tokens + cache_creation_input_tokens, cached = cache_read, cacheWrite = cache_creation, output = output_tokens.

### B.8 연결 확인 (실행 경로 열기) — [코드] `A/data/claude/ClaudeConnectionVerifier.kt`

사용자가 "구독으로 연결 확인" 을 눌렀을 때만 (90초 타임아웃). 검증 요청도 구독 사용량을 쓴다는 안내 표시.
1. epoch+1, 검증 플래그 모두 false 로 시작.
2. 프로필 재조회: profileId 같아야, `subscriptionType != null`, **`has_extra_usage_enabled == false` 여야**("추가 사용량을 끈 뒤 구독 연결을 다시 확인해 주세요.").
3. usage 조회: `extra_usage.is_enabled == false` 여야.
4. 강제 도구 왕복: tool `andy_verify_echo`(schema `{type:object, properties:{nonce:{type:string}}, required:[nonce], additionalProperties:false}`), system "You are verifying the connection. Only the supplied echo tool is available. Do not perform any user task.", user "Call andy_verify_echo with nonce <uuid>. After its result, answer OK only.", `max_tokens:128`, **`tool_choice:{"type":"tool","name":"andy_verify_echo"}`** → 응답이 완료 + tool_use 정확히 1개 + 이름·nonce 일치. 이어서 assistant 원본 content + `tool_result`(tool_use_id, content=nonce)를 붙여 `tool_choice` 없이 재요청 → 완료 + 도구 호출 없음 + 텍스트 있음.
5. 이미지 확인: 1×1 PNG base64 `iVBORw0KGgoAAAANSUhEUgAAAAEAAAABCAQAAAC1HAwCAAAAC0lEQVR42mP8/x8AAwMCAO+ip1sAAAAASUVORK5CYII=` + "If this image input is readable, reply OK.", max_tokens 32. HTTP 400 이면 이미지 미지원(false), 그 밖 오류는 실패.
6. usage 재조회: `extra_usage.is_enabled == false` 이고 `used_credits` 가 증가했으면 실패("추가 사용량 차감이 확인돼 구독 연결을 활성화하지 않았어요.").
7. 통과 → `subscriptionVerified=true, toolsVerified=true, imagesVerified=<5>`.

### B.9 오류 처리·재시도 — [코드] `A/data/claude/ClaudeClient.kt`

시도 루프 (HTTP call timeout 180s):
| 상황 | 처리 |
|---|---|
| 401, 아직 갱신 안 함 | 갱신(`afterUnauthorized`) 후 **같은 body** 재전송 (재시도 횟수 밖) |
| 401, 갱신 후 또 | `markUnusable` + 실패 `auth_required` "Claude 재연결이 필요해요." |
| 400 + 본문 `error.type=="invalid_request_error"` && `error.message` 가 `prompt is too long` 로 시작(대소문자 무시) | `context_length_exceeded` "대화가 너무 길어요. 요청을 나누거나 새 대화를 시작해 주세요." |
| 429 | `rate_limited` "Claude 요청 한도에 도달했어요. 잠시 후 다시 시도해 주세요." — **재시도 안 함**. (구독 한도 소진과 일반 rate limit 을 구분하지 않음 — Andy 미구현) |
| ≥500 (529 포함) | `http_<code>` 재시도 가능 |
| 그 밖 비성공 | `http_<code>` "Claude 요청이 실패했어요 (<code>)." 재시도 안 함 |
| IO 오류 | 스트림 시작 전이면 재시도, 시작 뒤면 `network` 실패 |
| 스트림 `error` 이벤트 | 위 B.7 (overloaded 만 재시도 가능하지만 스트림 시작 뒤라 실제로는 재시도 안 됨) |
재시도: 스트림이 시작되지 않았고 재시도 가능할 때만, 최대 2회(총 3시도), 대기 `500ms × 재시도번호`(500, 1000).
응답이 끝난 뒤 자격을 한 번 더 확인(그새 연결이 바뀌었으면 결과를 쓰지 않음).

### C.5 HTTP·SSE 를 Dart 로 옮길 때의 함정 (확인함)

1. **쿼리 인코딩**: Dart `Uri(queryParameters:)` 는 공백 → `+`. SIWC authorize 는 RFC3986(`%20`) 함수로 직접 조립(A.4). 폼 본문(`http.post(body: Map)`)은 `application/x-www-form-urlencoded` 로 `+` 가 나가는데, 폼 인코딩에선 정상이다.
2. **User-Agent**: dart:io 기본 UA = `Dart/3.12 (dart:io)` (확인함). Claude 요청은 `User-Agent: claude-cli/2.1.280` 을 명시 헤더로 넣는다 — `IOClient` 는 요청 헤더를 `headers.set` 으로 덮으므로 기본값이 대체된다(단위 테스트로 고정: 로컬 HttpServer 로 받은 헤더 확인). Claude 토큰 엔드포인트 요청 UA 는 Andy 도 OkHttp 기본값이었다(지정 안 함).
3. **gzip**: dart:io HttpClient 는 `Accept-Encoding: gzip` 을 붙이고 자동 해제 — SSE 에도 문제없음.
4. **SSE 스트리밍**: `client.send(request)` → `StreamedResponse.stream` 을 `utf8.decoder` → `LineSplitter` 로 변환(멀티바이트 경계 안전). `http.post` 는 본문을 다 받을 때까지 기다리므로 쓰지 않는다.
5. **취소**: `http ^1.6.0` 의 `AbortableRequest(abortTrigger: future)` 를 쓰거나, 요청마다 새 `http.Client` 를 만들고 구독 취소 시 `client.close()`. `Stream<String>` 의 `onCancel` 에서 abort.
6. **헤더 이름**: `session_id`(밑줄)는 HTTP 토큰 문자라 dart:io 가 허용.
7. **필드 순서**: `jsonEncode` 는 Map 삽입 순서를 지킨다 — 바디 Map 을 A.13/B.6 순서로 만든다.
8. **HttpServer 머리 8KB 제한**: dart:io HttpServer 가 HTTP 파싱을 맡으므로 Andy 의 수동 머리 읽기(8KB·5초)는 옮기지 않는다. 대신 `server.idleTimeout`·요청마다 처리 규칙(A.6 표)을 지킨다. 중복 키 판정은 `request.uri.queryParametersAll`.

### C.6 브라우저 열기와 앱 복귀

- macOS: 기존 `Process.run('open', [url])` 그대로 (하루 출시본에서 이미 동작). 앱 복귀는 사용자가 직접(결과 페이지 문구 "이 창을 닫고 하루로 돌아가 주세요").

  - 복귀 버튼(SIWC 결과 페이지): Andy 는 `intent://auth/done#Intent;scheme=andy;package=<pkg>;end` + `AuthReturnActivity`. 하루는 MainActivity 에 intent-filter(예: scheme `com.goldenplanet.solo_todo`, host `ai-auth-done`)를 추가하고 `intent://ai-auth-done#Intent;scheme=com.goldenplanet.solo_todo;package=com.goldenplanet.solo_todo;end` 링크를 넣는다. 기존 `login-callback` host 는 Supabase 가 쓰므로 재사용하지 않는다. 버튼이 안 되면 hint 문구로 충분하다.

### C.7 Android 에서 loopback 서버 주의점

1. `HttpServer.bind(InternetAddress.loopbackIPv4, 1455)` 는 Android 에서 동작한다(권한 = INTERNET, 이미 있음). Chrome 에서 `http://127.0.0.1:…` 으로 들어오는 요청은 앱의 cleartext 정책과 무관.
2. **프로세스가 얼거나 죽는 문제** — Andy 는 브라우저가 앞에 있는 동안 앱 프로세스가 cached 로 내려가 얼거나(LMK) 죽어 콜백을 못 받는 것을 막으려고 `LoginForegroundService`(`foregroundServiceType=specialUse`, 권한 `FOREGROUND_SERVICE`·`FOREGROUND_SERVICE_SPECIAL_USE`)를 띄운다(`LoginForegroundService.kt:28`). 하루에는 FGS 가 없다.
   - 얼어 있는 동안 들어온 연결은 커널 backlog 에 쌓였다가 앱이 다시 앞으로 오면 처리될 수 있지만, 브라우저 쪽은 그때까지 로딩 상태다. 프로세스가 죽으면 메모리의 verifier 가 사라져 그 시도는 실패 → 다시 로그인.
   - 하루 1차: FGS 없이 구현하고 실기기에서 확인(§F). 실패가 재현되면 FGS 를 추가(플러그인 또는 Kotlin 서비스 + 매니페스트 권한). 로그인 대기 화면에 "브라우저에서 승인한 뒤 하루로 돌아와 주세요" 안내와 [다시 열기]·[취소]를 둔다.
3. 포트: 1455 가 쓰이고 있으면 0(임의). [실측]은 1455 만 통과 확인, 다른 포트는 [미실측]이지만 [공식]이 1455 를 "예시"로 들고 Andy 코드는 임의 포트를 허용한다.
4. 앱이 백그라운드로 가도 Dart isolate 의 `HttpServer` 는 유지된다(프로세스가 살아 있는 한). 10분 타임아웃·취소 시 반드시 `close()` 로 포트를 푼다.
5. Android 앱 복귀(성공 뒤 앞으로 가져오기)는 Andy 도 백그라운드 액티비티 시작 제한으로 대부분 실패한다 — 결과 페이지 버튼(C.6)에 의존.

### C.8 id_token 검증 — 서명 검증 생략 가능 판단

- 판단: **RS256 서명 검증은 생략하고 claims 검증은 한다.** 근거: OpenID Connect Core 1.0 §3.1.3.7 (6) — id_token 을 클라이언트가 토큰 엔드포인트에서 TLS 로 직접 받았다면 서명 확인 대신 TLS 서버 검증을 쓸 수 있다. 하루는 `https://auth.openai.com/api/accounts/oauth/token` 응답에서만 id_token 을 받는다.
- 남기는 검사(새 패키지 불필요, `dart:convert` 로 payload base64url 디코드): 3조각 구조 → `iss == "https://auth.openai.com"` → `aud` ∋ 발급 client_id → `azp` 규칙 → `exp + 60 ≥ now` → `nonce` 일치(상수 시간) → `sub` 필수. 헤더 `alg` 는 `RS256` 이 아니면 거부(Andy 와 같은 방어, 비용 없음).
- 쓰임: `sub` = 계정 식별(accountKey, 재인가 시 같은 계정 확인), `email` = `login_hint`·표시, 원문 id_token = `id_token_hint`.
- 나중에 서명까지 하려면 `pointycastle` 을 직접 의존으로 올리고 JWKS(A.9 규칙)로 RS256 확인 — 지금은 불필요.

### D.2 ChatGPT 구현 — `ChatGptAiGateway`

공통 요청: `model = 설정 모델(기본 gpt-6-luna)`, `instructions`, `reasoning.effort = "low"`(모델 지원 목록에 없으면 목록 중 가장 낮은 값), `store:false`, `stream:true`, `prompt_cache_key = "haru-<기능>"`, `input = [{"role":"user","content": input}]`, 헤더 A.13 (`session_id = "haru-<기능>"`). 시도 루프 = A.11 401 흐름 + A.15 보조 정책.

`json()`:
1. 모드 `schema`(기본): `text = {"format":{"type":"json_schema","name":"haru_result","schema": toStrict(schema),"strict":true}}` 를 추가. 완료 → `outputText` 를 `jsonDecode` → Map 아니면 null. `refusal` 이면 null.
2. 400 이고 (`param` 이 `text` 또는 `text.format` 으로 시작) 또는 (code 없는 detail 에 `format`/`text.format` 포함) → 프로세스 플래그 `_schemaUnsupported = true` 로 바꾸고 3 으로 1회 재요청. [미실측 — 첫 실계정 점검에서 어느 모드로 도는지 확인]
3. 모드 `prompt`(Andy 방식): instructions 끝에 `"\n\n출력은 JSON 하나만, 다른 글 없이. 형식(JSON Schema):\n" + jsonEncode(schema)` 를 붙이고 text.format 없이 요청. 응답 텍스트에서 첫 `{` ~ 마지막 `}` 를 잘라 `jsonDecode` → Map 아니면 null (Andy `parseProposals`).
4. `response.incomplete` → null. 터미널 없는 EOF → AiNetwork(재시도 대상).

### D.3 Claude 구현 — `ClaudeAiGateway`

공통: 자격 = `ClaudeAccountStore.credential(requireTools: <json 이면 true>)`, 바디 B.6, `max_tokens = account.maxTokens(8192)`, 헤더 B.6, 시도 루프 B.9.

`json()` — **강제 도구** (Andy `ClaudeConnectionVerifier` 가 `tool_choice:{type:"tool",name}` 로 쓰는 방식):
```json
{"model":"<모델>","system":[billing, intro, instructions],
 "tools":[{"name":"haru_result","description":"Return the result as structured data.","input_schema": <schema>}],
 "tool_choice":{"type":"tool","name":"haru_result"},

```
→ `stop_reason == "tool_use"` + tool_use 블록 정확히 1개 + 이름 `haru_result` → 그 블록의 `input`(B.7 에서 JSON object 로 확인됨)을 반환. `max_tokens`/`refusal`/`model_context_window_exceeded` → null. 이름이 다르거나 블록이 없으면 null.
- 강제 도구는 확장 thinking 과 같이 쓸 수 없는데, 하루는 thinking 을 보내지 않으므로 해당 없음.
- 대체 방식(Andy 보조 호출 `LlmGateway.text` + `MemoryTidier.parseProposals`): 도구 없이 instructions 에 JSON 지시 → 텍스트에서 `{…}` 추출. 강제 도구가 거절되면(400) 이 방식으로 1회 재요청하도록 같은 구조를 둔다.

## 위험 (요약)

1. **Claude 경로는 Andy 에서도 실계정으로 한 번도 확인되지 않았다.** 로그인(Claude Code client_id 재사용·수동 redirect), 호환 헤더·billing 블록 수용, 구독 한도 차감이 전부 미검증이며, Anthropic 법적 고지(`code.claude.com/docs/en/legal-and-compliance`)는 제삼자 앱의 Claude.ai 로그인 제공·구독 자격 중개를 허용하지 않는다고 적고 있다(Andy `research/03` §3) — 서버 쪽 차단·계정 제재 가능성이 남는다.
