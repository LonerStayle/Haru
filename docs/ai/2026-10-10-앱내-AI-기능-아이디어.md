# 하루 앱 안 AI 기능 — 플랜 연동 + 아이디어 심사 (2026-10-10)

> 입력: Andy 플랜 로그인 분석, 하루 코드·데이터 브리핑, 발상 아이디어 25개
> 전제: 설정에서 Claude 플랜과 ChatGPT 플랜 로그인을 모두 지원하고, 그 플랜으로 앱 안 AI 기능을 쓴다. 회사 카테고리 제목 전송은 허용됨.
> 이 문서는 기획 심사 결과입니다. 코드는 아직 바꾸지 않았습니다.

---

## 1. 요약

**"그냥 두 플랜을 연동하는 것"이 왜 두 갈래로 나뉘는지**

- **ChatGPT 플랜**: OpenAI가 다른 앱용 "ChatGPT로 로그인"(SIWC)을 공식으로 열어 두었습니다. 그래서 하루 설정에 [ChatGPT로 로그인] 버튼을 두고 Andy 코드를 거의 그대로 옮기면 됩니다. macOS와 Android 모두 됩니다.
- **Claude 플랜**: Anthropic에는 다른 앱용 "Claude 계정으로 로그인" 기능이 없습니다. Andy는 이 기능을 "Claude Code인 척"하는 방식으로 붙였습니다. 즉 Claude Code의 client_id, 헤더, 지문을 흉내 냅니다. 이 방식은 Claude Code가 업데이트되면 깨지고, 실계정으로 검증된 적이 없고, 계정이 제한될 위험이 있어서 하루로 옮기지 않습니다.
- **그래도 Claude 플랜은 씁니다.** 맥에 깔린 **공식 Claude Code(`claude -p`)를 하루가 대신 불러 주는 방식**입니다. 대표님이 이미 로그인한 Claude 플랜을 공식 프로그램이 그대로 쓰므로, 결과적으로 "Claude 플랜 연동"과 같습니다. 다만 다음 두 가지는 따로 정해 주셔야 합니다.
  - 이 방식은 macOS에서만 됩니다.
  - 하루 macOS 앱의 샌드박스 문제를 먼저 풀어야 합니다(§2-3).

**기능 심사 결과**

25개를 겹치는 것끼리 합쳐 15개로 줄였습니다. 먼저 만들 것은 5개입니다. 모두 다음 원칙을 지킵니다.
- AI는 제안만 합니다. 할 일 데이터에 쓰는 것은 대표님이 눌렀을 때뿐입니다.
- 기존 저장 경로와 되돌리기를 그대로 탑니다.
- 기존 규칙으로 안 되는 경우에만 AI가 나섭니다.

| 순서 | 기능 | 한 줄 |
|---|---|---|
| T1 | 서술형 설명 → 목록 | 문장으로 적은 설명을 `- [ ]` 목록으로 바꿔 기존 DescriptionChecklist에 넘김. 가장 작아서 게이트웨이 첫 검증용 |
| T2 | 붙여넣기 정리 | 일괄 추가 대화상자에 [AI로 정리]를 두고, 회의록이나 메일에서 할 일 초안을 뽑음 |
| T3 | 오래된 할 일 정리 제안 | StaleBacklog 화면 행마다 완료 추정, 버리기, 다음 달, 장기 목표 칩을 붙임 |
| T4 | 다음 한 걸음 | 장기 목표나 아이디어 1건에 30분짜리 행동 3개를 제안하고, 하위 항목이나 오늘로 넣음 |
| T5 | ⌘K 물어보기 | 백로그에 질문하면 답과 근거 할 일 칩을 보여 줌. 읽기 전용 |

과거 기각 근거가 지금 어떻게 바뀌었는지 반영했습니다.
- 비용: 사라졌습니다.
- 하루 2~3건 규모: 입력 시점에 건별로 판정하는 기능(카테고리 제안, 중복 감지 등)은 여전히 약합니다. 쌓인 백로그를 한 번에 다루는 기능이나 붙여넣기 1회처럼 덩어리를 다루는 기능은 이 규모와 무관합니다.
- 자연어 날짜 1%: 대표님이 직접 타이핑한 제목의 통계입니다. 그래서 날짜 해석은 붙여넣기 기능(T2) 안에서만 씁니다.

## 2. 0단계 — 연동 자체 구현 (모든 기능의 선행 작업)

### 2-1. 공통 게이트웨이 (`lib/src/features/ai/`)

Andy `LlmGateway`를 하루 규모에 맞게 줄입니다. 에이전트나 도구 루프는 두지 않고 **단발 호출 2개**만 둡니다.

- `AiGateway.json({instructions, input, schema})` → `Map?`: 기능 대부분이 이것을 씁니다.
- `AiGateway.stream(...)` → `Stream<String>`: T5처럼 길게 답하는 기능만 씁니다.

경로와 준비 상태
- 경로는 `AiRoute { off, chatgptPlan, claudeCode }`입니다. `_SinglePrefNotifier` 패턴으로 저장하고, 기본값은 `off`입니다.
- 준비 판정은 `aiReadinessProvider` 한 곳에서 합니다. 기능 버튼은 준비됐을 때만 보입니다.

실패 처리
- **자동 폴백은 없습니다.** 실패하면 행 안에 "설정에서 확인" 안내를 보여 줍니다.
- 보조 호출은 실패하면 `null`을 돌려주고 조용히 생략합니다.

응답 검증
- 응답 JSON은 앱이 검증합니다.
- 입력에 없던 id나 카테고리 id는 버립니다('기타' 복원 함정 방지).
- 시각은 UTC ISO로 바꿉니다.

테스트
- `FakeAiGateway`를 둬서 기능 위젯 테스트가 네트워크 없이 돌게 합니다.

### 2-2. ChatGPT 플랜 (SIWC) — Andy에서 이식, macOS와 Android 모두

| 단계 | 내용 | 원본 |
|---|---|---|
| PKCE와 state | verifier 64B, state와 nonce 각 32B, S256 | `Pkce.kt`. 하루 `microsoft_auth_service.dart` 재사용 |
| 콜백 | `HttpServer.bind(loopbackIPv4, 1455)`, 실패하면 포트 0. 경로 `/auth/callback`. state 불일치는 400, 중복은 409. **`127.0.0.1`만 씀(localhost 금지)** | `LoopbackCallbackServer.kt` |
| 첫 등록 | `client_id=dynamic_agent_client`, `agent_name_hint=하루`, 기기별 `ext_agent_host_id=urn:uuid:…`. 콜백에 실려 오는 새 client_id를 저장 | `AuthorizeUrl.kt`, `SiwcAccountStore` |
| 토큰 | form POST, secret 없음. 교환과 갱신 모두 `resource=https://api.openai.com/v1`. refresh token은 매번 회전 | `TokenEndpoint.kt`, `scripts/siwc-dev-login.py` |
| id_token 검증 | RS256, JWKS, iss, aud, nonce. **패키지 1개 추가 필요**(`jose` 계열) | `IdTokenVerifier.kt` |
| 저장 | 앱 지원 디렉터리의 파일. 임시 파일에 쓴 뒤 rename하는 **원자적 쓰기**. 키체인은 쓰지 않음(기존 MS 토큰과 같은 방식) | — |
| 갱신 | 만료 5분 전에 갱신. **single-flight**로 한 번에 하나만. `refresh_token_reused` 등이 나면 토큰을 지우고 재로그인 요구 | `SiwcCredentialProvider.kt` |
| 호출 | `POST /v1/responses`, SSE, `store:false`. `max_output_tokens`는 넣지 않음. 401이 나면 강제 갱신 후 1회만 재시도 | `OpenAiClient.kt` |
| 모델 | `GET /v1/models`로 계정별 목록을 받음. 하드코딩하지 않음 | `ModelCatalog*.kt` |
| 한도 | 429 `usage_limit_exceeded`가 나면 30분 멈추고 `chatgpt.com/settings/usage` 링크를 보여 줌. 403은 반복하지 않음. 503은 간격을 늘려 재시도 | `OpenAiError.kt`, `UsagePause.kt` |
| 로그아웃 | refresh token을 revoke(1·2·4초 간격 재시도)하고 토큰 3종을 지움. client_id와 host id는 남김 | — |

**공통 규칙**
- 토큰은 Supabase로 동기화하지 않습니다. 맥과 폰에서 각각 로그인합니다.
- 토큰, code, authorize URL은 로그에 남기지 않습니다.

**Android 주의**
- 브라우저로 넘어간 동안 앱 프로세스가 죽을 수 있습니다.
- 1차 구현은 서비스 없이 시험합니다. 2FA처럼 오래 걸려 대기가 끊기면 그때 포그라운드 서비스를 추가합니다.
- 콜백 페이지의 "앱으로 돌아가기"는 기존 `com.goldenplanet.solo_todo://` 스킴을 재사용합니다.

### 2-3. Claude 플랜 — 공식 Claude Code를 하루가 불러 쓰는 방식 (macOS)

동작
- 하루가 `Process.run('claude', ['-p', <프롬프트>, '--output-format', 'json', ...])`를 단발로 실행합니다. 도구는 쓰지 않습니다.
- 로그인과 플랜 과금은 대표님이 이미 로그인해 둔 Claude Code가 처리합니다. 하루는 토큰을 보관하지 않습니다.

설정 화면 표시
- `claude --version`과 로그인 상태를 보여 줍니다.
- 설치되어 있지 않거나 로그아웃 상태면 "터미널에서 `claude` 로그인 필요"라고 안내합니다.

**막히는 지점: 샌드박스**
- 하루 macOS 앱은 `app-sandbox`가 켜져 있습니다.
- 하루가 띄운 `claude`도 샌드박스를 그대로 물려받기 때문에, `~/.claude`에 있는 인증 정보와 키체인에 접근하지 못할 가능성이 높습니다.

해결안은 셋입니다.
1. **하루 macOS 빌드에서 샌드박스를 끕니다.** 개인용으로 로컬에 설치하는 앱이라 가능합니다.
   - 단, 앱 지원 디렉터리가 컨테이너(`~/Library/Containers/...`) 밖으로 바뀝니다. 그래서 **drift DB, MS 토큰, 설정 파일을 옮기는 단계가 필수**입니다. 옮기지 않으면 첫 실행 때 빈 앱처럼 보입니다.
2. 샌드박스 밖에 작은 헬퍼(LaunchAgent)를 두고 하루가 소켓으로 요청합니다. 하루 데이터 경로는 그대로지만 설치와 서명이 복잡해집니다.
3. 하루에서는 Claude 경로를 두지 않습니다(ChatGPT만).

→ 먼저 **반나절 스파이크**를 권합니다. 샌드박스가 켜진 Release 빌드에서 `claude -p "ping" --output-format json`이 성공하는지 확인합니다. 성공하면 위 결정은 필요 없습니다.

**Android에서는 Claude 플랜을 쓸 수 없습니다.** 선택지는 셋입니다.
- (a) Android의 AI는 ChatGPT 플랜만 씁니다(권장).
- (b) Supabase에 `ai_jobs` 큐를 두고, 켜져 있는 맥이 대신 처리합니다(맥이 꺼져 있으면 대기).
- (c) Anthropic API 키(종량 과금)를 씁니다.

### 2-4. 설정 화면 (⌘, / 모바일 설정)

"AI" 섹션을 새로 둡니다.
- **사용할 AI**: 끔 / ChatGPT 플랜 / Claude(맥의 Claude Code)
- **ChatGPT 플랜**: 계정 이메일과 플랜 표시, [로그인]/[로그아웃], 모델 선택, 한도 상태
- **Claude**: 설치와 로그인 상태, [연결 확인]
- **[연결 확인]**: 짧은 JSON 왕복 1회. Andy의 연결 확인 게이트를 단순화한 것입니다.
- **보내는 내용**: "제목, 카테고리 이름, 설명 앞 300자"를 고정 안내합니다. 설명 전송은 토글로 둡니다.

### 2-5. 0단계 검증 항목

- 단위 테스트

  - 콜백 서버의 state, 경로, 중복 처리

  - 원자적 저장
  - 에러 코드 매핑
- 실계정 체크리스트

  - 토큰 만료 후 갱신
  - 로그아웃 후 재로그인
  - 429 한도 표시

## 3. 먼저 만들 것 Top 5

### T1. 서술형 설명 → `- [ ]` 목록 (원안 5와 8 병합)

- **MVP**: 설명이 80자 이상이고 목록 기호가 없을 때만 설명칸 아래에 "목록으로" 칩을 보여 줍니다. AI 결과는 **설명 텍스트를 바꾸기만** 합니다. 하위 항목으로 바꾸는 일은 기존 DescriptionChecklist 제안 행이 그대로 맡고, 되돌리기를 지원합니다.
- **AI가 필요한 이유**: 규칙은 목록 기호가 있을 때만 동작합니다. '~하고, 끝나면 ~'처럼 문장으로 적은 설명은 의미 단위로 나눠야 합니다.
- **먼저 고르는 이유**: 바뀌는 곳이 설명 텍스트 하나라 피해 상한이 가장 낮습니다. 0단계 게이트웨이를 끝까지 검증하기에 가장 좋습니다.
- **착수 전 확인**: DB에서 "설명 80자 이상 + 목록 기호 없음 + 미완료" 건수를 셉니다. 거의 없으면 T2로 대체합니다.

### T2. 붙여넣기 정리 — 일괄 추가 대화상자 [AI로 정리] (원안 1과 2 병합. 클립보드 칩과 공유는 나중)

- **MVP**: `bulk-paste-dialog`에 세 번째 버튼을 둡니다. 누르면 초안 패널에 항목마다 체크, 제목, 카테고리 칩, 날짜 칩, 근거 구절을 보여 줍니다. 저장은 기존 `_submitBulk`를 거칩니다.
  - 날짜는 원문에 명시된 것만 넣습니다.
  - 날짜가 붙은 항목은 캘린더에 등록되므로 미리 표시합니다.
  - 하위 항목은 1단계 깊이만 만듭니다.
  - 되돌리기는 한 번에 전체를 취소합니다.
- **AI가 필요한 이유**: 문장 다시 잇기, 소제목과 하위 묶기, 할 일이 아닌 줄 버리기, 제각각인 날짜 표기 해석은 `splitBulkLines`로는 할 수 없습니다.
- **착수 전 확인**: 일괄 추가 대화상자가 열린 횟수를 로컬 카운터로 2주 동안 셉니다. 이 카운터는 0단계와 병행해도 됩니다.

### T3. 오래된 할 일 정리 제안 (원안 7, 18, 24 병합)

- **MVP**: StaleBacklog 화면의 [제안 받기]를 누르면 행마다 칩(완료 추정 / 다음 주 / 다음 달 / 장기 목표로 / 유지)과 근거 한 줄을 붙입니다.
  - 칩을 누를 때만 기존 `_complete`/`_schedule`/이동 경로를 탑니다.
  - '완료 추정'은 2단계로 확인합니다.
  - '유지'는 칩을 숨깁니다.
  - 삭제, 합치기, 자동 선택은 없습니다.
- **AI가 필요한 이유**: 규칙은 "오래됐다"까지만 압니다. 끝났는지, 언제 할 일인지, 장기 목표로 보낼 일인지는 의미를 읽어야 압니다.
- **빈도**: 월 1회 정도라 낮습니다. 그 대신 수십 건을 한 번에 처리하므로 하루 2~3건 규모와 무관합니다.

### T4. 다음 한 걸음 (원안 11, 17, 22 병합)

- **MVP**: 상세 패널에 "다음 한 걸음" 버튼을 둡니다. 장기 목표나 개인 아이디어 카테고리이고 하위 항목이 0개인 항목에만 보입니다.
  - 결과는 30분 이내 행동 3개입니다.
  - 각 행동에 [하위로 추가] [하위로 + 오늘로]를 둡니다.
  - 저장은 기존 addChild 경로를 쓰고 되돌리기를 지원합니다.
  - 카테고리 화면에 카드로 일괄 제안하는 방식은 나중에 합니다.
- **AI가 필요한 이유**: 주제를 행동으로 바꾸는 것은 생성 작업이라 규칙으로 할 수 없습니다. 날짜 없는 백로그가 오늘 화면으로 넘어오는 통로가 됩니다.
- **착수 전 확인**: 장기 목표와 아이디어 카테고리의 미완료 건수, 그중 하위 항목이 없는 비율을 셉니다.

### T5. ⌘K 물어보기 (원안 14)

- **MVP**: ⌘K에서 `?`로 시작하면 물어보기 모드로 바뀝니다. Android는 검색 화면 상단에 [검색 | 물어보기] 세그먼트를 둡니다.
  - 미완료 항목과 최근 14일 완료 항목을 압축 JSON으로 보냅니다. 설명은 앞 300자만 보내고 토글로 끌 수 있습니다.
  - 답은 스트리밍으로 보여 주고, 근거 할 일 칩을 누르면 해당 항목을 엽니다.
  - **쓰기 경로가 0인 읽기 전용**입니다.
- **AI가 필요한 이유**: "30분 안에 끝날 것", "회사 일 중 막힌 것"처럼 설명을 읽어야 답할 수 있는 질문은 필터로 만들 수 없습니다.
- **주의**: 매 질문이 수천~1만 토큰이라 플랜 한도를 가장 많이 씁니다. ChatGPT Plus의 5시간 한도는 다른 앱과 함께 씁니다.

**권장 착수 순서**: 0단계(ChatGPT 경로 먼저, Claude 스파이크 병행) → T1 → T2 → T3 → T4 → T5

## 5. 나중에 / 하지 말 것

**나중에** (Top 5가 자리를 잡고 사용 데이터가 쌓인 뒤)
- **M3 제목 다듬기**: 원문을 설명에 보존하면 안전합니다. 다만 120자 이상 제목이 281건 중 몇 건인지부터 셉니다.
- **M9 오늘 고르기**: 규칙 기준선(진행중 우선, 마감 지남, 오래됨)과 체감 차이가 작을 수 있습니다. 규칙 버전을 먼저 만들고 AI는 보강으로 붙입니다.
- **M5 카테고리 교정 / 재배치**: 제목→카테고리 281건으로 앱 밖 오프라인 벤치마크를 돌려 90% 이상일 때만 만듭니다. 기본은 꺼 둡니다.
- **M2 음성**: 마이크와 음성 인식 권한, entitlement가 추가로 필요합니다. T2의 초안 패널과 스키마가 생기면 비용이 크게 줄어듭니다.
- **M1 확장(클립보드 칩, Android 공유 시트)**: T2가 실제로 쓰이는 것이 확인된 뒤에 붙입니다.
- **M13 주간 회고, M11 자연어 지시, M12 대화 탭**: 일괄 쓰기, 롤백, 다중 턴 UI 비용에 비해 체감이 불확실합니다. M11의 실행기(id 화이트리스트, 스냅샷 롤백)는 T3·T4가 쌓인 뒤에 공통 컴포넌트로 고려합니다.

**하지 말 것**
- **M7 백로그 합치기**: 삭제가 포함되는 파괴적 동작이고 캘린더에 연결된 항목이 고아가 될 위험이 있습니다. 필요하면 T3 칩에 "같은 일 묶기(삭제 없이 한 부모 아래로)"만 추가합니다.
- **M15 반복 찾기**: `supabase_todos_api.dart`가 반복 4개 컬럼을 동기화하지 않아 parity가 깨집니다. 대표님이 반복 기능을 실제로 쓴 적도 없습니다. 반복 동기화를 먼저 고치기 전에는 착수하지 않습니다.
- **M14 빈 시간에 넣기**: 날짜 없는 백로그 중심 사용과 맞지 않습니다. Google과 MS 두 캘린더의 바쁜 구간 계산, 시간대 사고 이력, 일정 잘못 생성 위험에 비해 효용이 낮습니다.
- **Andy식 Claude 위장 로그인**: §2-3의 공식 Claude Code 호출로 대체합니다.
- **에이전트, 도구 루프, 메모리 회상, 자동화 트리거**: 하루 규모에 비해 과합니다.
