## 4. 대표님과 정해야 할 것 (본문 §7)

대화는 이 순서가 자연스럽다 — 앞의 답이 뒤의 선택지를 좁힌다.

1. **어떤 불편부터 풀고 싶은가** (목적 확인)
   - 입력이 귀찮다 → A 묶음(자동 카테고리 A1, 자연어 파싱 A2)
   - 이월이 쌓인다 → B2 이월 정리
   - 큰 일을 못 쪼갠다 → B1 하위 쪼개기
   - 돌아보고 싶다 → C 묶음(브리핑·회고)
   → 1차 범위(추천: A1 · A2 · B1 + 인프라) 동의 여부
2. **개인 데이터 전송 범위** — 제목만 / 제목+설명 / 기능별 선택. 기본 끔 + 켜면 안내 방식에 동의하는지
3. **LLM 키** — Anthropic API 키를 Supabase 비밀값으로 둘지(앱에는 키를 절대 안 넣는 설계)
4. **JEV 얼리 액세스 신청 여부** — 신청 전에는 같은 판정을 LLM(Haiku) 구조화 출력으로 먼저 만들고, 승인되면 교체해 속도·비용 비교하는 안

추가로 물어볼 만한 것:
- 제안 칩이 뜨는 게 거슬리지 않을지(빠른 추가 직후 "→ 회사 할일?" 한 번). 싫으면 편집 시트 안에서만
- 모바일에서도 같은 기능을 원하는지(기본은 양쪽 parity)
- 비용 상한(월 얼마까지 괜찮은지)
- Phase 4 와 순서 — AI 먼저 / Phase 4 먼저 / ⌘K 는 함께

## 5. 지켜야 할 규칙 (대화 중 제안할 때도)

- **AI 는 제안, 쓰기는 대표님 탭** — 자동 저장·자동 이동·자동 정렬 금지. 받아들이면 되돌리기(⌘Z) 가능
- 기존 앱 규칙과 충돌 금지: 순서는 명시적 조작으로만 / 탭 = 상세 / 편집 시트 닫힘 = 저장 / 입력→저장 200ms 체감(AI 는 저장 뒤 비동기)
- 키는 서버(Supabase Edge Function)에만. 외부 텍스트(캘린더 초대·붙여넣은 메일)는 동작 승인 근거로 쓰지 않는다(JEV 프롬프트 인젝션 사례)
- 파괴적 동작(일괄 삭제·이동)은 AI 판정과 무관하게 항상 확인 + 되돌리기
- 호칭 "대표님", 경어, 짧게. 결정이 필요한 건 AskUserQuestion 으로
